# User Feedback dans les Systèmes de Recommandation

## Introduction : Sources de connaissance

Un système de recommandation s'appuie sur deux types de connaissances :

### 1. **Connaissance de l'utilisateur (User)**
- **Données historiques** : Interactions passées avec les items
  - Achats, clics, vues, ratings, etc.
- **Démographiques** : Profil sociodémographique
  - Âge, genre, nationalité, opinions politiques, revenu, etc.
- **Contexte** : Informations situationnelles
  - Device utilisé, localisation, moment (jour/semaine/année)
  - Seul ou en groupe

### 2. **Connaissance de l'item**
- **Informations de contenu**
  - Features, tags, texte descriptif
  - Images, signaux multimédia
  - Métadonnées (genre, acteurs, réalisateur pour un film)

---

## Types de Feedback Utilisateur

Il existe deux grandes catégories de feedback que les utilisateurs fournissent aux systèmes :

---

## 1. 📊 Feedback Explicite (Explicit Feedback)

### Définition
> Le feedback explicite est une forme de retour d'information **directement rapportée** par l'utilisateur au système.

### Types de feedback explicite

| Type | Description | Exemple |
|------|-------------|---------|
| **Ratings (échelle 5 étoiles)** | Notes sur une échelle graduée | ⭐⭐⭐⭐⭐ "New favorite!!!" <br> ⭐⭐⭐⭐ "Enjoyed it!" <br> ⭐⭐⭐ "Mixed feelings." <br> ⭐⭐ "Did not like it." <br> ⭐ "Hated it!" |
| **Like/Dislike** | Binaire (pouce up/down) | 👍 👎 |
| **Ordinal scale** | Échelle à 3 niveaux | 🟢 Agree <br> 🟡 Neutral <br> 🔴 Disagree |
| **Textual reviews** | Commentaires textuels | "I love the new design!!" #amazing <br> "The food was delicious, but the waiters were so rude..." |

### Avantages du feedback explicite
✅ **Signal clair** : Intention directe de l'utilisateur  
✅ **Facile à interpréter** : Pas d'ambiguïté sur la préférence  
✅ **Quantifiable** : Peut être utilisé directement pour la prédiction  

---

### ⚠️ Limitations du feedback explicite

Le feedback explicite présente plusieurs problèmes majeurs :

#### 1. **Les utilisateurs ne fournissent pas toujours de feedback**
- Effort cognitif requis
- La plupart des utilisateurs sont passifs
- Seulement une petite fraction note/commente

#### 2. **Le système peut être incapable de collecter le feedback**
- Exemple : Impossible de demander à noter les personnes dans "People You May Know" de LinkedIn
- Certaines interactions ne se prêtent pas au rating

#### 3. **Le rating révèle-t-il la vraie opinion de l'utilisateur ?**
- **Biais d'humeur** : État émotionnel au moment du rating
- **Influence sociale** : L'utilisateur peut être influencé par son cercle social
- **Désirabilité sociale** : Noter selon ce qui est "acceptable"

#### 4. **Rating du package complet vs. détails spécifiques**
- Un utilisateur note-t-il l'expérience globale ?
- Ou un aspect particulier affecte le rating global ?
- Exemple film : Note globale vs. performance d'un acteur spécifique

#### 5. **Le feedback explicite exhibe des biais**
- **Biais de générosité** : Certains utilisateurs donnent systématiquement des notes plus élevées
- **Biais de sévérité** : D'autres sont plus critiques
- **Niveau de calibration différent** : Un 4/5 pour Alice ≠ 4/5 pour Bob

---

## 2. 🔍 Feedback Implicite (Implicit Feedback)

### Définition
> Le feedback implicite est collecté par le système **sans intervention active** de l'utilisateur.

### Types de feedback implicite

| Type | Description | Signal |
|------|-------------|--------|
| **Clicks** | Clics sur un item | L'utilisateur a montré de l'intérêt |
| **Purchases** | Achats effectués | Signal fort de préférence |
| **Views** | Consultation de la description | Niveau d'intérêt variable |
| **Add to Wishlist** | Ajout à une liste de souhaits | Intention future |
| **Time spent** | Durée sur une page | Plus de temps = plus d'intérêt ? |
| **Play/Stream** | Visionnage d'une vidéo/film | Consommation effective |
| **Search queries** | Termes recherchés | Intention et besoin |

### Avantages du feedback implicite
✅ **Abondant** : Chaque interaction génère du feedback  
✅ **Pas d'effort utilisateur** : Collecte automatique  
✅ **Représente le comportement réel** : Actions concrètes  
✅ **Continuous** : Flux constant de données  

---

### ⚠️ Défis du feedback implicite

#### 1. **Le feedback implicite est intrinsèquement bruité (noisy)**

**Problème :** Chaque item positif (interagi) **n'est pas nécessairement** un item aimé.

**Exemples de bruit :**
- Clic accidentel
- Achat pour quelqu'un d'autre (cadeau)
- Visionnage mais déçu du contenu
- Explorer sans vraiment apprécier

#### 2. **Il n'y a pas de feedback négatif**

**Problème majeur :** Les items "négatifs" sont un **mélange** de :
- ❌ Items que l'utilisateur n'aime pas
- ❓ Items que l'utilisateur ne connaît pas (unknowns)

**Conséquence :**
```
Items non-interagis = {Items non aimés ∪ Items inconnus}
```

On ne peut pas distinguer entre :
- "Je n'ai pas cliqué parce que ça ne m'intéresse pas"
- "Je n'ai pas cliqué parce que je ne suis pas au courant de son existence"

## 3. 📋 Matrices de Feedback

### Matrice de Feedback Explicite

Une matrice utilisateur × item avec des ratings :

|  | 🎬 Barbie | 🎬 Anatomy of a Fall | 🎬 Wonka | 🎬 Film 4 | 🎬 The Marvels | 🎬 Migration |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| 😊 **User 1** | 4 | - | 5 | 1 | - | - |
| 😊 **User 2** | - | - | - | 5 | 4 | 3 |
| 😊 **User 3** | - | 3 | 1 | 5 | - | - |
| 😊 **User 4** | 2 | 2 | - | - | 5 | 4 |
| 😊 **User 5** | - | 5 | - | 2 | - | - |

**Caractéristiques :**
- Valeurs : Notes de 1 à 5
- Beaucoup de cases vides (sparsité)
- Signal clair : 5 = j'adore, 1 = je déteste
- **Problème** : Peu de données (la plupart des cases sont vides)

---

### Matrice de Feedback Implicite (Binaire)

Même utilisateurs, mais feedback binaire (1 = interagi, vide = pas d'interaction) :

|  | 🎬 Barbie | 🎬 Anatomy of a Fall | 🎬 Wonka | 🎬 Film 4 | 🎬 The Marvels | 🎬 Migration |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| 😊 **User 1** | 1 | - | 1 | 1 | - | - |
| 😊 **User 2** | - | - | - | 1 | 1 | 1 |
| 😊 **User 3** | - | 1 | 1 | 1 | - | - |
| 😊 **User 4** | 1 | 1 | - | - | 1 | 1 |
| 😊 **User 5** | - | 1 | - | 1 | - | - |

**Caractéristiques :**
- Valeurs : 0 ou 1 (binaire)
- 1 = Interaction observée (achat, clic, vue, etc.)
- Vide = Pas d'interaction
- **Plus de données** que le feedback explicite
- **Moins d'information par interaction** (on ne sait pas si c'est vraiment apprécié)

---

### Matrice de Feedback Implicite (Pondérée/Weights)

Version avancée : chaque interaction a un poids basé sur le type/intensité :

|  | 🎬 Barbie | 🎬 Anatomy of a Fall | 🎬 Wonka | 🎬 Film 4 | 🎬 The Marvels | 🎬 Migration |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| 😊 **User 1** | 2.0 | - | 2.8 | 0.8 | - | - |
| 😊 **User 2** | - | - | - | 3.2 | 2.4 | 1.0 |
| 😊 **User 3** | - | 1.2 | 1.0 | 2.0 | - | - |
| 😊 **User 4** | 0.4 | 0.9 | - | - | 2.1 | 1.3 |
| 😊 **User 5** | - | 3.0 | - | 0 | - | - |

**Calcul des poids :**
- **Acheté** : Poids élevé (3.0)
- **Ajouté wishlist** : Poids moyen (2.0)
- **Cliqué/Vu description** : Poids faible (0.5-1.0)
- **Temps passé** : Pondération proportionnelle
- **Combinaison** : Somme ou moyenne pondérée des actions

**Avantages :**
- Capture l'intensité de l'intérêt
- Plus nuancé que le binaire
- Utilise toutes les interactions disponibles

## 4. 🔄 Comparaison Explicite vs Implicite

| Critère | Feedback Explicite | Feedback Implicite |
|---------|-------------------|-------------------|
| **Collecte** | Demande effort utilisateur | Automatique |
| **Quantité** | Peu de données | Beaucoup de données |
| **Qualité** | Signal clair mais biaisé | Signal bruité |
| **Feedback négatif** | Oui (rating bas) | Non (ambiguïté) |
| **Interprétation** | Directe | Nécessite inférence |
| **Temps réel** | Non (utilisateur doit agir) | Oui (continu) |
| **Sparsité** | Très sparse | Moins sparse |
| **Utilisabilité** | Idéal pour rating prediction | Idéal pour ranking/Top-N |

## 5. 💡 Implications pour les Systèmes de Recommandation

### Stratégies selon le type de feedback

#### Avec Feedback Explicite :
- ✅ Utiliser pour **Rating Prediction**
- ✅ Collaborative Filtering classique
- ✅ Matrix Factorization (SVD, Funk SVD)
- ⚠️ Gérer la sparsité (peu de données)
- ⚠️ Traiter les biais utilisateurs (normalisation)

#### Avec Feedback Implicite :
- ✅ Utiliser pour **Top-N Recommendation**
- ✅ Learning to Rank (BPR, listwise)
- ✅ One-Class Collaborative Filtering
- ⚠️ Gérer le bruit dans les positifs
- ⚠️ Gérer l'absence de feedback négatif

### Approches hybrides (recommandé)

**Combiner les deux types** pour tirer parti des avantages de chacun :

```
Feedback Total = α × Feedback_Explicite + β × Feedback_Implicite
```

**Exemple Netflix :**
- Ratings explicites (étoiles) → Indique préférence claire
- Viewing behavior (temps regardé) → Indique engagement réel
- Completion rate → Indique satisfaction
- **Combinaison** : Pondération selon fiabilité de chaque signal

---

## 6. 🎯 Meilleures Pratiques

### Pour collecter du feedback de qualité :

1. **Minimiser l'effort utilisateur**
   - Interface simple et intuitive
   - Rating en un clic
   - Feedback optionnel, pas obligatoire

2. **Contextualiser les demandes**
   - Demander feedback au bon moment
   - Juste après consommation d'un item
   - Pas trop fréquemment (fatigue)

3. **Diversifier les sources**
   - Ne pas se reposer uniquement sur un type
   - Croiser feedback explicite et implicite
   - Utiliser le contexte (temps, localisation)

4. **Traiter intelligemment les données**
   - Normaliser les ratings (gérer biais)
   - Pondérer le feedback implicite
   - Filtrer le bruit (outliers, comportements anormaux)

5. **Feedback loops**
   - Permettre à l'utilisateur de corriger
   - "Why was this recommended?" → Transparence
   - "Not interested" → Feedback négatif explicite

---

## Conclusion

Le feedback utilisateur est le **carburant** des systèmes de recommandation :

- **Feedback Explicite** : Signal clair mais rare et biaisé
- **Feedback Implicite** : Abondant mais bruité et sans négativité claire
- **Solution optimale** : **Combiner les deux** et traiter intelligemment les limitations de chacun

> "Plus de données bat un algorithme plus complexe" - Pedro Domingos

Mais la **qualité** et l'**interprétation correcte** du feedback sont tout aussi cruciales que la quantité !
