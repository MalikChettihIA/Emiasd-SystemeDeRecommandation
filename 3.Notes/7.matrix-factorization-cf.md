## 1. 🎯 Introduction et Motivation {#intro}

### 1.1 Limites des Approches Memory-Based

Les approches **k-NN** (Memory-Based CF) présentent des limitations :

**❌ Problèmes :**
- **Scalabilité** : Calcul des similarités coûteux (O(n²))
- **Sparsité** : Performance dégradée avec données sparses
- **Pas d'apprentissage** : N'extrait pas de patterns latents
- **Sensibilité au bruit** : Utilise données brutes

---

### 1.2 Solution : Model-Based Approaches

**Matrix Factorization (MF)** est une approche model-based qui :

✅ **Apprend un modèle compact** représentant les données  
✅ **Découvre facteurs latents** (hidden features)  
✅ **Réduit la dimensionnalité** (de m × n à k dimensions, k << m, n)  
✅ **Robuste au bruit** (régularisation)  
✅ **Scalable** : Prédictions rapides après training  

---

## 2. 🧩 Framework de Matrix Factorization {#framework}

### 2.1 Principe Fondamental

**Idée centrale :**
> Représenter **utilisateurs** et **items** dans un **espace commun de facteurs latents** de dimension K.

**Facteurs latents** = Caractéristiques cachées, non observées directement

**Exemples de facteurs latents pour films :**
- Genre (action, romance, sci-fi)
- Époque (moderne, classique)
- Cible démographique (enfants, adultes)
- Complexité narrative
- Budget de production
- ...

Ces facteurs ne sont **pas définis manuellement**, mais **appris automatiquement** depuis les données !

---

### 2.2 Décomposition Matricielle

**Objectif :** Décomposer la matrice de ratings **R** en deux matrices de facteurs latents :

```
        m items
     ┌──────────┐
     │          │
   n │    R     │  Feedback matrix (sparse)
     │          │
     └──────────┘
           ≈
     ┌────┐   ┌──────────┐
   n │ P  │ × │  Q^T     │ K
     │    │   └──────────┘
     └────┘       m items
       K
```

**Formulation mathématique :**
```
R ≈ P × Q^T
```

**Où :**
- **R** : Rating matrix (n × m) - sparse, beaucoup de valeurs manquantes
- **P** : User latent matrix (n × K) - chaque ligne = représentation user
- **Q** : Item latent matrix (m × K) - chaque ligne = représentation item
- **K** : Nombre de facteurs latents (dimensionnalité)

---

### 2.3 Interprétation des Matrices

#### Matrice P (User features)

```
        Factor 1  Factor 2  Factor 3  ...  Factor K
        (Action)  (Romance) (SciFi)        
User 1  [  0.8      0.1       0.9     ...    0.3   ]
User 2  [  0.2      0.9       0.1     ...    0.5   ]
User 3  [  0.5      0.5       0.7     ...    0.8   ]
...
User n  [  0.3      0.2       0.4     ...    0.6   ]
```

**Valeurs de P :**
> Représentent **à quel point l'utilisateur est attiré par** ou a une certaine caractéristique

**Exemple :** 
- User 1 aime l'action (0.8) et la sci-fi (0.9), mais pas la romance (0.1)

---

#### Matrice Q (Item features)

```
         Factor 1  Factor 2  Factor 3  ...  Factor K
         (Action)  (Romance) (SciFi)
Item 1   [  0.9      0.0       0.2     ...    0.4   ]
Item 2   [  0.1      0.95      0.0     ...    0.3   ]
Item 3   [  0.7      0.1       0.8     ...    0.6   ]
...
Item m   [  0.4      0.3       0.5     ...    0.7   ]
```

**Valeurs de Q :**
> Représentent **à quel point l'item possède** une certaine caractéristique

**Exemple :**
- Item 1 est un film d'action (0.9) avec peu de sci-fi (0.2) et pas de romance (0.0)

---

### 2.4 Hypothèse de Matrix Factorization

**Formule de prédiction :**
```
r̂_ui = p_u · q_i^T
```

**Où :**
- **r̂_ui** : Rating prédit de user u pour item i
- **p_u** : Vecteur latent de l'utilisateur u (ligne de P)
- **q_i** : Vecteur latent de l'item i (ligne de Q)
- **·** : Produit scalaire

**Interprétation :**
> Le rating prédit est le **produit scalaire** entre le vecteur utilisateur et le vecteur item dans l'espace latent.

---

### 2.5 Exemple Concret

```
User u = [0.8,  0.1,  0.9]  (aime action et sci-fi, pas romance)
Item i = [0.9,  0.0,  0.8]  (film d'action et sci-fi, pas romance)

r̂_ui = 0.8×0.9 + 0.1×0.0 + 0.9×0.8
     = 0.72 + 0 + 0.72
     = 1.44

→ Rating prédit élevé (user et item alignés)
```

```
User u = [0.8,  0.1,  0.9]  (aime action et sci-fi)
Item j = [0.1,  0.95, 0.0]  (film romantique)

r̂_uj = 0.8×0.1 + 0.1×0.95 + 0.9×0.0
     = 0.08 + 0.095 + 0
     = 0.175

→ Rating prédit faible (user et item non alignés)
```

### 2.6 Tâche d'Apprentissage

**Learning task :**
> Déterminer les matrices **P** et **Q** étant donné **R** (ratings observés)

**Challenge :**
- R est **sparse** (beaucoup de valeurs manquantes)
- On ne connaît que les ratings observés
- Objectif : Apprendre P et Q qui reconstituent **au mieux** les ratings observés

**Plusieurs approches possibles :**
1. **SVD** (Singular Value Decomposition)
2. **Gradient Descent** (SGD)
3. **Alternating Least Squares** (ALS)

---

## 3. 📐 Singular Value Decomposition (SVD) {#svd}

### 3.1 Principe de la SVD

**Théorème SVD :**
> Toute matrice R (n × m) peut être décomposée en :

```
R = U × Σ × V^T
```

**Où :**
- **U** : Matrice orthogonale (n × n) - vecteurs propres gauches
- **Σ** : Matrice diagonale (n × m) - valeurs singulières σ₁ ≥ σ₂ ≥ ... ≥ σ_min
- **V^T** : Matrice orthogonale (m × m) - vecteurs propres droits

---

### 3.2 Visualisation SVD

```
┌─────┐       ┌─────┐   ┌─────────┐   ┌─────────┐
│     │       │ /// │   │ σ₁      │   │ /////   │
│  R  │   =   │ /// │ × │   σ₂    │ × │ /////   │ K
│     │       │ /// │   │     σ₃  │   │ /////   │
└─────┘       └─────┘   │       ..│   └─────────┘
 n×m           n×n      │      σₖ │      m×m
                        └─────────┘
                           n×m
```

---

### 3.3 Approximation Rank-K

**Idée :** Garder seulement les **K plus grandes valeurs singulières**

```
R̂ = Σ(s=1 to K) σ_s p_s q_s^T
```

**Visuellement :**

```
┌─────┐       ┌───┐   ┌─────┐   ┌─────────┐
│     │       │ /│    │ σ₁  │   │ /////   │
│  R  │  ≈    │ /│  × │  σ₂ │ × │ /////   │ K
│     │       │ /│    │   σₖ│   │ /////   │
└─────┘       └───┘   └─────┘   └─────────┘
 n×m          n×K      K×K         K×m

            P             Σ_K         Q^T
```

**Résultat :**
- **P** (n × K) : U × Σ_K^(1/2) → User latent matrix
- **Q** (m × K) : V × Σ_K^(1/2) → Item latent matrix

---

### 3.4 Problème de Sparsité avec SVD

**⚠️ Challenge majeur :**
> Appliquer SVD pour Collaborative Filtering : **Sparsity issue**

**Problème :**
- SVD nécessite une matrice **complète** (pas de valeurs manquantes)
- Mais R est **très sparse** (99%+ de valeurs manquantes !)

**Solutions naïves (mauvaises) :**
1. **Remplir avec 0** : Incorrect (0 ≠ "non noté")
2. **Remplir avec moyenne** : Imprécis et **très coûteux**

**Conséquence :**
> SVD classique n'est **pas directement applicable** au problème de recommandation

---

### 3.5 Solution : Optimisation Directe

Au lieu d'utiliser SVD, **apprendre P et Q directement** en minimisant une fonction de perte sur les ratings **observés uniquement**.

→ Conduit aux approches **Gradient Descent** et **ALS**

---

## 4. 📉 Minimisation du Squared Loss {#squared-loss}

### 4.1 Fonction Objectif

**Objectif :** Apprendre P et Q pour minimiser l'erreur de reconstruction

**Fonction de perte avec régularisation :**

```
min   || R - PQ^T ||²_F + λ(||P||²_F + ||Q||²_F)
P, Q
```

**Décomposition :**

```
ℒ(P, Q) = Σ (r_ui - p_u·q_i^T)² + λ(Σ||p_u||² + Σ||q_i||²)
         (u,i)∈𝒟                  u=1        i=1
```

**Où :**
- **𝒟** : Ensemble des ratings **observés** (paires (u,i) avec r_ui connu)
- **||·||²_F** : Norme de Frobenius au carré
- **λ** : Paramètre de régularisation (hyperparamètre)

---

### 4.2 Composantes de la Loss

#### 4.2.1 Terme de Reconstruction

```
Σ (r_ui - p_u·q_i^T)²
(u,i)∈𝒟
```

**Interprétation :**
- Minimise l'**erreur quadratique** entre ratings observés et prédits
- Ne considère **que les ratings observés** (pas de problème de sparsité)

---

#### 4.2.2 Terme de Régularisation

```
λ(Σ||p_u||² + Σ||q_i||²)
  u         i
```

**Interprétation :**
- **Pénalise** les valeurs trop grandes dans P et Q
- **Évite l'overfitting** : Empêche le modèle de trop s'ajuster aux données observées
- **λ** contrôle l'importance de la régularisation

**Trade-off :**
- **λ petit** : Modèle s'ajuste bien aux données (risque overfitting)
- **λ grand** : Modèle plus simple (risque underfitting)

---

### 4.3 Visualisation du Processus

```
Matrice R (sparse)        Approximation PQ^T
┌────────────┐           ┌────────────┐
│ 1  ?  5  ? │           │ 1.2 3.1 4.8│
│ ?  4  ?  3 │    ≈      │ 2.5 4.1 3.5│
│ 2  ?  ?  4 │           │ 2.1 3.0 3.2│
└────────────┘           └────────────┘

    ↓ Minimiser erreur uniquement sur cellules observées

Erreur = (1-1.2)² + (5-4.8)² + (4-4.1)² + (3-3.5)² + (2-2.1)² + (4-3.2)²
       + Régularisation
```

## 5. 🔄 Algorithmes d'Apprentissage {#algorithms}

### 5.1 Stochastic Gradient Descent (SGD)

#### Principe

**Idée :**
> Mettre à jour les paramètres **pour chaque observation** (u, i) individuellement

**Avantages :**
- ✅ **Plus rapide** que Gradient Descent classique
- ✅ Converge rapidement en pratique

**Inconvénient :**
- ❌ Nécessite fixer le **learning rate η** (hyperparamètre)

---

#### Règles de Mise à Jour

**Pour chaque observation (u, i) ∈ 𝒟 :**

```
e_ui = r_ui - p_u·q_i^T   (erreur)

p_u ← p_u - η ∂ℒ/∂p_u
q_i ← q_i - η ∂ℒ/∂q_i
```

**Calcul des gradients :**

```
∂ℒ/∂p_ul = 2q_il(p_u·q_i^T - r_ui) + 2λp_ul
         = 2e_ui·q_il + 2λp_ul

∂ℒ/∂q_il = 2p_ul(p_u·q_i^T - r_ui) + 2λq_il
         = 2e_ui·p_ul + 2λq_il
```

**Simplification (avec η incorporant le facteur 2) :**

```
p_u ← p_u - η(e_ui·q_i + λp_u)
q_i ← q_i - η(e_ui·p_u + λq_i)
```

---

#### Algorithme SGD Complet

```
Algorithm 2: Stochastic Gradient Descent (SGD)

Input:  Rating matrix R
        Set of observed ratings 𝒟
        Stopping criterion ϵ
        Rank K
        Learning rate η
        Regularization parameter λ

Output: Optimal user matrix P, optimal item matrix Q

1  Initialize P and Q randomly
2  while not converged, e.g., ||R - PQ^T|| > ϵ do
3      for each (u,i) ∈ 𝒟 do
4          e_ui = p_u·q_i^T - r_ui
5          p_u ← p_u - 2η(e_ui·q_i + λp_u)
6          q_i ← q_i - 2η(e_ui·p_u + λq_i)
7      end for
8  end while
```

**Critère de convergence :**
- Vérifier si l'erreur totale ||R - PQ^T|| < ϵ (seuil)
- Ou nombre maximum d'itérations atteint

---

### 5.2 Alternating Least Squares (ALS)

#### Principe

**Idée :**
> **Itérer** sur les paramètres : fixer l'un, optimiser l'autre, et vice-versa

**Observation clé :**
- Si **Q est fixé**, problème devient **convexe** en P (régression linéaire)
- Si **P est fixé**, problème devient **convexe** en Q (régression linéaire)

**Avantages :**
- ✅ Pas de learning rate à tuner
- ✅ **Parallélisable** : Calculs indépendants pour chaque user/item
- ✅ Convergence garantie à un minimum local

---

#### Algorithme ALS

```
Algorithm 3: Alternating Least Squares (ALS)

Input:  Rating matrix R
        Regularization parameter λ

Output: Optimal user matrix P, optimal item matrix Q

1  Initialize P and Q randomly
2  while not converged do
3      for u ∈ 1,...,n do                         ▷ Update users
4          p_u ← (Σ q_i·q_i^T + λI)^(-1) Σ r_ui·q_i
                i∈ℐ_u                    i∈ℐ_u
5      end for
6      for i ∈ 1,...,m do                         ▷ Update items
7          q_i ← (Σ p_u·p_u^T + λI)^(-1) Σ r_ui·p_u
                u∈𝒰_i                    u∈𝒰_i
8      end for
9  end while
```

**Notations :**
- **ℐ_u** : Ensemble des items notés par user u
- **𝒰_i** : Ensemble des users ayant noté item i
- **I** : Matrice identité (K × K)

---

#### Interprétation des Mises à Jour

**Update user u (ligne 4) :**

```
p_u = (Q_u^T·Q_u + λI)^(-1)·Q_u^T·r_u
```

- **Q_u** : Sous-matrice de Q contenant lignes des items notés par u
- **r_u** : Vecteur des ratings de u

→ Solution analytique de la **régression linéaire régularisée**

**Analogie :**
- **P fixé** : Chaque q_i est solution d'un problème de **régression linéaire** avec features P
- **Q fixé** : Chaque p_u est solution d'un problème de **régression linéaire** avec features Q

---

### 5.3 Comparaison SGD vs ALS

| Aspect | SGD | ALS |
|--------|-----|-----|
| **Hyperparamètres** | η (learning rate) + λ | λ uniquement |
| **Convergence** | Plus rapide (en epochs) | Plus lent (en epochs) |
| **Parallélisation** | ❌ Difficile (updates séquentiels) | ✅ Excellente (indépendance) |
| **Complexité par iter** | O(\|𝒟\| × K) | O(\|𝒟\| × K²) |
| **Tuning** | ⚠️ Sensible à η | ✅ Moins sensible |
| **Cas d'usage** | Petits datasets, prototypage | Grands datasets, production |

## 6. 🎯 Au-delà du Squared Loss {#beyond-squared}

### 6.1 Problème du Rating Prediction

**Contexte traditionnel :**
- **Task** : Matrix completion (compléter la matrice)
- **Objectif** : Prédire ratings manquants avec précision
- **Métrique** : RMSE (Root Mean Squared Error)
- **Fonction objectif** : Squared loss

**Limitation :**
> Dans les systèmes réels, il est **plus important** de fournir une **liste bien ordonnée** que de prédire avec précision toutes les valeurs numériques.

---

### 6.2 Évolution vers le Ranking

Avec l'évolution du problème de recommandation, **plusieurs fonctions objectifs** ont été explorées :

#### 6.2.1 Point-wise Functions

**Exemple :** Squared loss

```
ℓ^point(r_ui, r̂_ui) = (r_ui - r̂_ui)²
```

**Caractéristique :**
- Focus sur **précision des préférences individuelles**
- Traite chaque rating indépendamment

---

#### 6.2.2 Pair-wise Functions

**Exemple :** BPR (Bayesian Personalized Ranking)

```
ℓ^pair(r_uij, r̂_uij)
```

**Caractéristique :**
- Considère le **classement relatif** de paires d'items
- Optimise : "Item i devrait être classé plus haut que item j"

**Avantage :**
- Plus adapté au problème de **Top-N recommendation**
- Optimise directement le ranking

---

#### 6.2.3 List-wise Functions

**Exemple :** NDCG loss, ListNet

**Caractéristique :**
- Reflète la **distance** entre la liste recommandée complète et la liste de référence
- Considère la liste dans son ensemble

**Avantage :**
- Optimisation directe de métriques de ranking (NDCG, MAP)
- Plus aligné avec l'objectif final

---

### 6.3 Comparaison des Approches

```
┌──────────────────────────────────────────────────┐
│         POINT-WISE (Squared Loss)                │
├──────────────────────────────────────────────────┤
│  Optimise : |r_ui - r̂_ui|                        │
│  Focus    : Précision des ratings                │
│  Métrique : RMSE, MAE                            │
└──────────────────────────────────────────────────┘
                     ↓
┌──────────────────────────────────────────────────┐
│         PAIR-WISE (BPR)                          │
├──────────────────────────────────────────────────┤
│  Optimise : Classement relatif (i > j)           │
│  Focus    : Ordre entre paires d'items           │
│  Métrique : AUC, Precision@k                     │
└──────────────────────────────────────────────────┘
                     ↓
┌──────────────────────────────────────────────────┐
│         LIST-WISE (NDCG Loss)                    │
├──────────────────────────────────────────────────┤
│  Optimise : Distance liste complète              │
│  Focus    : Qualité globale du ranking           │
│  Métrique : NDCG, MAP                            │
└──────────────────────────────────────────────────┘
```

---

### 6.4 Implications Pratiques

**Choix de la fonction de perte selon l'objectif :**

| Objectif Business | Fonction Recommandée |
|-------------------|---------------------|
| Prédire ratings précis | Point-wise (Squared loss) |
| Top-N recommendations | Pair-wise (BPR) |
| Optimiser métriques ranking | List-wise (NDCG loss) |

## 7. 📊 Résumé et Comparaison

### 7.1 Memory-Based vs Model-Based

| Aspect | Memory-Based (k-NN) | Model-Based (MF) |
|--------|---------------------|------------------|
| **Calcul** | Similarités directes | Apprentissage de modèle |
| **Scalabilité** | ❌ Mauvaise | ✅ Excellente |
| **Sparsité** | ⚠️ Problématique | ✅ Gère bien |
| **Interprétabilité** | ✅ Haute | ⚠️ Facteurs latents abstraits |
| **Performance** | ⭐⭐ Moyenne | ⭐⭐⭐⭐ Supérieure |
| **Cold start** | ❌ Difficile | ⚠️ Difficile aussi |

---

### 7.2 Avantages de Matrix Factorization

✅ **Scalabilité** : Prédictions en O(K) après training  
✅ **Découverte de patterns latents** : Capture structures cachées  
✅ **Robustesse** : Régularisation contre overfitting  
✅ **Performance** : État de l'art sur beaucoup de benchmarks  
✅ **Flexibilité** : Extensions possibles (bias, temporal dynamics, etc.)  

---

### 7.3 Limitations de Matrix Factorization

❌ **Interprétabilité** : Facteurs latents difficiles à interpréter  
❌ **Cold start** : Nouveaux users/items problématiques  
❌ **Linéarité** : Assume interactions linéaires (p_u · q_i)  
❌ **Hyperparamètres** : K, λ, η à tuner  

---

## Conclusion

**Matrix Factorization** est une approche puissante pour Collaborative Filtering :

🎯 **Principe** : Décomposer R en P × Q^T dans espace latent  
🔢 **Apprentissage** : Minimiser squared loss avec régularisation  
⚙️ **Algorithmes** : SGD (rapide) ou ALS (parallélisable)  
📈 **Performance** : Supérieure aux approches memory-based  
🚀 **Extensions** : Pair-wise, list-wise loss pour ranking  

**Prochaines étapes possibles :**
- Ajouter **biais** (user bias, item bias)
- Intégrer **temporal dynamics**
- Utiliser **Deep Learning** (Neural Collaborative Filtering)
- Approches **hybrides** (MF + content-based)

> Matrix Factorization reste la **base fondamentale** des systèmes de recommandation modernes ! 🌟
