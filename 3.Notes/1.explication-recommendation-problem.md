# Le Problème de Recommandation

## 1. Deux approches du problème de recommandation

### 1.1 Rating Prediction (Prédiction de notes)

**Objectif principal :**
- Prédire la note (rating) qu'un utilisateur donnerait à un item qu'il n'a pas encore évalué

**Caractéristiques :**
- **Objectif** : Minimiser l'erreur entre les notes prédites et les notes observées
- **Recommandation** : Proposer les items ayant les notes prédites les plus élevées pour l'utilisateur
- **Métrique** : Précision de la prédiction (ex: RMSE - Root Mean Squared Error)

**Limitation importante :**
> Dans les systèmes réels, il est plus précieux de fournir des recommandations pertinentes en haut de liste que de prédire avec précision toutes les notes, y compris celles des items en bas de liste.

**Pourquoi cette limitation ?**
- L'utilisateur ne voit que les premiers items recommandés
- Une erreur de prédiction sur un item que l'utilisateur ne verra jamais n'a pas d'impact
- Ce qui compte vraiment : avoir les bons items en haut de la liste

---

### 1.2 Top-N Recommendation (Recommandation Top-N)

**Objectif principal :**
- Prédire la **pertinence** (relevance) d'un item pour un utilisateur
- C'est-à-dire : prédire si l'utilisateur va choisir cet item ou non

**Caractéristiques :**
- Focus sur le **classement** plutôt que sur la valeur exacte
- Problème binaire ou de ranking : "l'utilisateur va-t-il interagir avec cet item ?"
- Plus adapté à la réalité d'utilisation (l'utilisateur voit une liste ordonnée)

---

## 2. Formulation Générale du Problème

### 2.1 Notation mathématique

Soit :
- **𝒰** : L'ensemble des utilisateurs (users)
- **ℐ** : L'ensemble des items

### 2.2 Fonction d'utilité

On définit une **fonction f** qui mesure l'utilité d'un item pour un utilisateur :

```
f : 𝒰 × ℐ → ℝ
```

Où :
- **f(u, i)** représente l'utilité de l'item *i* pour l'utilisateur *u*
- **ℝ** est un ensemble totalement ordonné (par exemple : les nombres réels)
- Cette fonction peut représenter :
  - Un **rating** (note de 1 à 5 étoiles)
  - Une **relevance** (score de pertinence)
  - Une **probabilité** d'interaction

### 2.3 Objectif de recommandation

Pour chaque utilisateur *u* ∈ 𝒰, on cherche à recommander l'item *i\** qui maximise f :

```
∀u ∈ 𝒰, i* = arg max f(u, i)
                i∈ℐ
```

**Interprétation :**
- On cherche l'item qui a la plus grande valeur de f pour cet utilisateur
- En pratique, on recommande les **N items** ayant les scores f les plus élevés

## 3. Algorithme de Recommandation Standard

### 3.1 Algorithme général

```
Algorithm 1: A recommendation algorithm

Input: user u, number of items to recommend N

1  for i in ℐ \ ℐ_u do
2      Predict r̂_ui
3  end for
4  Create list of ℐ \ ℐ_u items ordered by decreasing order of r̂_ui
5  Return N first items of the list
```

### 3.2 Explication détaillée

**Notations :**
- **ℐ_u** : Ensemble des items déjà évalués/consommés par l'utilisateur *u*
- **ℐ \ ℐ_u** : Ensemble des items **non encore évalués** par l'utilisateur *u*
- **r̂_ui** : Score prédit pour l'utilisateur *u* et l'item *i*

**Étapes :**

1. **Boucle sur les items non évalués** (ligne 1-3)
   - Pour chaque item *i* que l'utilisateur n'a pas encore vu
   - Calculer un score prédit **r̂_ui** avec l'algorithme de recommandation

2. **Création de la liste ordonnée** (ligne 4)
   - Trier tous les items par ordre **décroissant** de score prédit
   - Les items avec les scores les plus élevés sont en haut

3. **Retour des Top-N** (ligne 5)
   - Renvoyer les **N premiers items** de la liste ordonnée
   - Ce sont les items les plus pertinents pour l'utilisateur

## 4. Différences clés entre les deux approches

| Aspect | Rating Prediction | Top-N Recommendation |
|--------|-------------------|---------------------|
| **Objectif** | Prédire la note exacte | Prédire la pertinence/choix |
| **Optimisation** | Minimiser RMSE sur toutes les paires (u,i) | Maximiser la qualité du ranking |
| **Évaluation** | MAE, RMSE | Precision@k, Recall@k, NDCG |
| **Cas d'usage** | Systèmes avec ratings explicites | Feedback implicite (clics, achats) |
| **Focus** | Précision globale | Qualité du top de la liste |

---

## 5. Implications pratiques

### 5.1 Pourquoi le Top-N est souvent préféré ?

1. **Interface utilisateur réelle**
   - L'utilisateur voit une liste de 5-20 items
   - Seuls les premiers items comptent vraiment
   
2. **Feedback implicite**
   - Souvent on n'a pas de ratings explicites
   - On observe des clics, achats, vues (binaire)
   
3. **Métriques business**
   - Ce qui compte : clics, conversions sur les items recommandés
   - Pas la précision de prédiction sur tous les items

### 5.2 Quand utiliser Rating Prediction ?

- Systèmes avec **ratings explicites** (ex: IMDb, Yelp)
- Quand on veut **expliquer** pourquoi on recommande (ex: "on pense que vous noteriez 4.5/5")
- Pour **calibrer** les attentes de l'utilisateur
- Comme **étape intermédiaire** avant le ranking

---

## 6. Formulation unifiée

Les deux approches peuvent être vues comme des cas particuliers :

```
f(u, i) peut représenter :
  - Un rating prédit : r̂_ui ∈ [1, 5]
  - Un score de pertinence : s(u,i) ∈ [0, 1]
  - Une probabilité : P(interaction | u, i)
```

**L'essentiel reste le même :**
> Calculer un score f(u,i) pour chaque paire (utilisateur, item) et recommander les items avec les scores les plus élevés.

---

## Conclusion

Le problème de recommandation se résume à :

1. **Définir** une fonction d'utilité f(u,i)
2. **Prédire** cette fonction pour les items non vus
3. **Ordonner** les items par score décroissant
4. **Recommander** les Top-N items

La différence principale entre Rating Prediction et Top-N Recommendation est le **focus** :
- Rating Prediction : précision sur toutes les prédictions
- Top-N : qualité du classement en haut de liste

**En pratique moderne**, l'approche Top-N domine car elle est plus alignée avec l'usage réel et les métriques business.
