### 2. Neural Matrix Factorization (NeuMF)
- Combinaison de GMF (General Matrix Factorization) et MLP
- **GMF Layer** : Produit élément par élément des vecteurs utilisateur/item
- **MLP Layers** : Réseau dense pour capturer les interactions non-linéaires
- **NeuMF Layer** : Combinaison des deux approches
- Formule : ŷ_ui = σ(w_GMF·GMF(p_u, q_i) + w_MLP·MLP(p_u, q_i) + b)

## 📚 PDF 4 - Reinforcement Learning pour Recommender Systems

### 1. Introduction au Learning to Rank (LTR)
- **Différence avec prédiction de ratings** :
  - LTR se concentre sur l'ordre, pas sur les valeurs exactes
  - Plus important d'avoir le bon classement que la bonne note
- **Pourquoi LTR ?** :
  - L'utilisateur voit une liste ordonnée
  - Seuls les premiers items comptent vraiment
  - Optimisation directe de l'objectif business

### 2. Types d'algorithmes LTR
- **Pointwise** :
  - Traite chaque item indépendamment
  - Prédit un score pour chaque item
  - Puis trie par score
  - Exemple : Régression logistique
  
- **Pairwise** :
  - Compare des paires d'items
  - Apprend quel item doit être classé plus haut
  - Exemple : RankNet, LambdaRank
  
- **Listwise** :
  - Considère la liste entière
  - Optimise directement une métrique de ranking
  - Plus complexe mais souvent meilleures performances
  - Exemple : ListNet, AdaRank

### 3. Exemple Foursquare
- **Contexte** : Recommandation de lieux géolocalisés
- **Features utilisées** :
  - Distance géographique
  - Popularité du lieu
  - Préférences utilisateur
  - Contexte temporel (jour/heure)
  - Social : amis ayant visité
- **Objectif** : Maximiser les check-ins

### 4. Re-ranking
- **Principe** : Post-traitement des recommandations
- **Objectifs** :
  - Diversification
  - Équité
  - Business rules
  - Fraîcheur (nouveaux items)
- **Exemple** : Boosting de nouveaux items ou sous-représentés

### 5. Bayesian Personalized Ranking (BPR)
- **Tâche à résoudre** : Ranking pour feedback implicite
- **Principe** :
  - Utilisateur préfère items vus aux items non vus
  - Apprendre à ordonner items observés > items non observés
  
- **Training data** :
  - Triplets (u, i, j) où :
    - u : utilisateur
    - i : item positif (consommé)
    - j : item négatif (non consommé)
  - Assumption : u préfère i à j

### 6. Mathématiques BPR
- **Fonction objectif** :
  - Maximiser : Σ ln(σ(x̂_uij))
  - x̂_uij = x̂_ui - x̂_uj (différence de scores)
  - σ : fonction sigmoïde
  
- **Régularisation** : Éviter l'overfitting
- **Optimisation** : Stochastic Gradient Descent
- **Sampling** : Échantillonnage aléatoire des triplets

### 7. Algorithme BPR
1. **Initialisation** : Facteurs aléatoires pour users et items
2. **LearnBPR** :
   - Pour chaque triplet (u, i, j) :
     - Calculer x̂_uij
     - Mettre à jour paramètres par gradient descent
3. **Répéter** jusqu'à convergence

### 8. BPR avec Matrix Factorization
- **Représentation** :
  - Vecteur utilisateur : p_u
  - Vecteur item positif : q_i
  - Vecteur item négatif : q_j
- **Score** : x̂_ui = p_u · q_i
- **Ranking score** : x̂_uij = p_u · (q_i - q_j)

### 9. Implémentation MovieGEEKs
- **Transformation des ratings** :
  - Rating > seuil → Positif
  - Rating ≤ seuil → Négatif ou ignoré
  - Génération des triplets
  
- **Draw method** :
  - Échantillonnage uniforme des utilisateurs
  - Pour chaque user : item positif aléatoire
  - Item négatif aléatoire parmi non vus
  
- **Training loop** :
  - Plusieurs epochs
  - Update des facteurs à chaque triplet
  
- **Génération de recommandations** :
  - Calculer scores pour tous items
  - Trier par score décroissant
  - Filtrer items déjà vus

### 10. Évaluation du Ranking
- **Métriques spécifiques** :
  - **NDCG@k** : Normalized Discounted Cumulative Gain
  - **MAP@k** : Mean Average Precision
  - **MRR** : Mean Reciprocal Rank
  - **Precision@k** : Précision sur les k premiers
  - **Recall@k** : Rappel sur les k premiers

### 11. Comparaison approches
- **Rating Prediction** : Minimise RMSE
- **Ranking** : Optimise ordre de présentation
- **Impact** : Meilleur engagement utilisateur avec ranking

## 📚 PDF 12 - Cold Start Problem

### 1. Définition du Cold Start
- **Problème majeur** des systèmes de recommandation
- **Trois types** :
  - Cold visitors (nouveaux utilisateurs)
  - Cold products (nouveaux items)
  - Gray sheep (utilisateurs atypiques)

### 2. Cold Visitors (Nouveaux utilisateurs)
- **Problème** : Aucun historique de comportement
- **Impact** : Impossible de personnaliser
- **Solutions** :
  - **Association rules** : Recommandations basées sur patterns généraux
  - **Popularity-based** : Items les plus populaires
  - **Demographic** : Segmentation par démographie
  - **Onboarding** : Demander préférences initiales

### 3. Cold Products (Nouveaux items)
- **Problème** : Aucune interaction utilisateur
- **Impact** : Items jamais recommandés
- **Solutions** :
  - **Content-based** : Utiliser métadonnées
  - **Expert reviews** : Recommandations éditoriales
  - **Early adopters** : Cibler utilisateurs aventureux
  - **Random injection** : Exploration forcée

### 4. Gray Sheep (Moutons gris)
- **Problème** : Préférences uniques, difficiles à modéliser
- **Caractéristiques** :
  - Goûts éclectiques
  - Ne ressemble à aucun groupe
  - Historique incohérent
- **Solutions** :
  - Diversification des recommandations
  - Approches hybrides
  - Permettre feedback explicite

### 5. Association Rules pour Cold Start
- **Principe** : "Si X alors Y"
- **Métriques** :
  - **Support** : Fréquence de l'ensemble {X, Y}
  - **Confidence** : P(Y|X) = Support(X,Y) / Support(X)
  - **Lift** : Confidence / Support(Y)

### 6. Algorithme Association Rules
1. **Trouver itemsets fréquents** :
   - Items de taille 1 avec support > seuil
   - Combiner pour taille 2, 3, etc.
   
2. **Générer règles** :
   - Pour chaque itemset fréquent
   - Générer toutes partitions possibles
   - Calculer confidence
   
3. **Filtrer** :
   - Confidence > seuil
   - Trier par confidence ou lift

### 7. Implémentation MovieGEEKs
- **get_all_transactions** : Récupérer historiques
- **calculate_support** : Items taille 1
- **combine_itemsets** : Générer tailles supérieures
- **save_to_database** : Stockage des règles
- **retrieve_by_confidence** : Recommandations

### 8. Evaluation Cold Start
- **Méthodes** :
  - Simulation nouveaux utilisateurs
  - Masquer historique récent
  - Mesurer performance avec peu de données
- **Métriques** :
  - Coverage : % users ayant des recommandations
  - Precision/Recall avec peu d'interactions

### 9. User Tracking pour Cold Start
- **Données collectables immédiatement** :
  - Device type
  - Location
  - Time of day
  - Referrer
  - Search queries
- **Utilisation** :
  - Segmentation initiale
  - Recommandations contextuelles

### 10. Stratégies combinées
- **Approche progressive** :
  1. Popularity (0 interactions)
  2. Association rules (1-5 interactions)
  3. Demographics + content (5-20 interactions)
  4. Collaborative filtering (20+ interactions)
  5. Full personalization (50+ interactions)

### 11. Asking User for Information
- **Quoi demander** :
  - Genres préférés
  - Items favoris (select from list)
  - Ratings de quelques items populaires
- **Balance** :
  - Ne pas surcharger l'utilisateur
  - Information actionnable immédiatement
  - Progressive disclosure

### 12. Domain Knowledge et Business
- **Expertise métier** :
  - Saisonnalité
  - Tendances
  - Événements
- **Business rules** :
  - Promotions
  - Stock disponible
  - Marges
- **Application** :
  - Boosting d'items stratégiques
  - Filtering d'items non disponibles

## 📚 PDF 13 - Non-Personalized Recommendations

### 1. Importance des recommandations non-personnalisées
- **Cas d'usage** :
  - Page d'accueil (utilisateur non connecté)
  - Nouveaux visiteurs
  - Fallback quand personnalisation impossible
- **Avantages** :
  - Simples à implémenter
  - Rapides à calculer
  - Pas de problème de cold start
  - Baseline pour évaluation

### 2. Popularity-Based Recommendations
- **Principe** : Items les plus consommés/aimés
- **Variantes** :
  - **Most viewed** : Plus vus
  - **Most purchased** : Plus achetés
  - **Highest rated** : Mieux notés
  - **Trending** : Populaires récemment
  
- **Fenêtre temporelle** :
  - All time : Classiques
  - Last month : Tendances
  - Last week : Actualité
  - Configurable selon besoins

### 3. Charts et Trends
- **Types de charts** :
  - Top 10 overall
  - Top par catégorie
  - Nouveautés populaires
  - Rising stars (croissance rapide)
  
- **Calcul** :
  - Agrégation des interactions
  - Pondération par récence
  - Normalisation par exposition

### 4. Comparaison Popularity vs Commercials
- **Commercials** (Publicité) :
  - Choisis par éditeur
  - Objectifs business
  - Pas basés sur données
  
- **Popularity** :
  - Basé sur comportement réel
  - Preuve sociale
  - S'adapte automatiquement
  
- **Hybride** : Mix des deux approches

### 5. Implémentation MovieGEEKs
- **Ajout au site** :
  - Section "Popular Movies"
  - Section "Trending This Week"
  - Charts par genre
  
- **Code architecture** :
  - Calcul périodique (batch)
  - Cache des résultats
  - API pour récupération
  
- **Rendre contenu attractif** :
  - Images de qualité
  - Descriptions accrocheuses
  - Social proof (nombre de vues/ratings)

### 6. Editorial Spotlights
- **Exemple DZone.com** :
  - Articles mis en avant
  - Sélection éditoriale
  - Mix avec algorithmique
  
- **Application** :
  - Nouveaux items à promouvoir
  - Contenu sponsorisé
  - Événements spéciaux

### 7. Seeded Recommendations (Association Rules)
- **Principe** : "Souvent achetés ensemble"
- **Amazon FBT** : Frequently Bought Together
- **Application** :
  - Page produit
  - Panier d'achat
  - Email post-achat

### 8. Temporal Aspects
- **Time-based popularity** :
  - Heure de la journée
  - Jour de la semaine
  - Saison
  - Events (Noël, etc.)
  
- **Decay functions** :
  - Exponentiel : Poids décroît rapidement
  - Linéaire : Décroissance constante
  - Step : Par paliers

### 9. Metrics pour Non-Personalized
- **Coverage** : Diversité des items recommandés
- **Freshness** : Renouvellement des recommandations
- **Click-through rate** : Taux de clic
- **Conversion** : Passage à l'achat

### 10. Limitations
- **Pas de personnalisation** : Même reco pour tous
- **Filter bubble inversée** : Tout le monde voit le même
- **Effet Matthew** : Riches deviennent plus riches
- **Solutions** :
  - Diversification forcée
  - Rotation des items
  - Segmentation basique (genre, location)

## 📚 PDF 6 - Filtrage Collaboratif

### 1. Introduction au Collaborative Filtering
- Définition : Recommandations basées uniquement sur les interactions utilisateur-item
- Histoire : Tapestry (premier système CF)
- Principe : Utilisateurs similaires aiment des items similaires

### 2. Rating Matrix
- Représentation matricielle utilisateurs × items
- Problème de sparsité (beaucoup de valeurs manquantes)
- Objectif : Prédire les valeurs manquantes

### 3. Types de Collaborative Filtering

#### 3.1 User-User Collaborative Filtering
- Trouver des utilisateurs similaires
- Utiliser leurs ratings pour prédire
- Calcul de similarité entre utilisateurs

#### 3.2 Item-Item Collaborative Filtering
- Trouver des items similaires
- Plus stable que user-user
- Meilleure scalabilité
- Implémentation :
  - Calcul offline de la similarité entre items
  - Prédictions online rapides
  - Suppression des similarités avec peu de chevauchement

### 4. Calcul de similarité
- **Jaccard Distance** : Pour données binaires
- **Lp-norms** :
  - L1-Norm (Manhattan distance)
  - L2-Norm (Euclidean distance)
- **Cosine Similarity** : Angle entre vecteurs
- **Pearson Similarity** : Corrélation linéaire

### 5. Sélection du voisinage (Neighborhood)
- **Méthodes** :
  - Clustering (k-means)
  - Threshold de similarité
  - Top-N approach
- Trouver le bon équilibre : trop petit = peu de données, trop grand = bruit

### 6. Calcul des prédictions
- **Régression** : Prédiction de la note exacte
- **Classification** : Catégorisation (aime/n'aime pas)
- Formules :
  - Moyenne pondérée des ratings voisins
  - Prise en compte des biais utilisateur/item

### 7. Implémentation MovieGEEKs
- Calcul offline des similarités items
- Stockage en base de données
- Génération de recommandations online
- Suppression des similarités faibles

### 8. K-means Clustering
- **Algorithme** :
  1. Initialiser k centroïdes aléatoirement
  2. Assigner chaque point au centroïde le plus proche
  3. Recalculer les centroïdes
  4. Répéter jusqu'à convergence
- **Implémentation Python** :
  - Distance au centroïde le plus proche
  - Utilisation des clusters pour segmentation
  - Warning : Peut converger vers optimum local

### 9. Leviers d'optimisation pour CF
- Taille du voisinage
- Seuil de similarité minimale
- Normalisation des ratings
- Gestion des items populaires vs. niche

### 10. Avantages et inconvénients
- **Pros** :
  - Pas besoin de connaître le contenu
  - Serendipity (découvertes surprenantes)
  - Améliore avec le temps
- **Cons** :
  - Cold start (nouveaux users/items)
  - Sparsité des données
  - Scalabilité
  - Popularity bias

## 📚 PDF 7 - Matrix Factorization

### 1. Réduction de dimensionnalité
- Pourquoi réduire : Performance, débruitage
- Trouver des facteurs latents (hidden genres)

### 2. Exemple illustratif
- Préférences utilisateurs pour différents genres
- Découverte automatique de patterns

### 3. Algèbre linéaire (rappel)
- **Matrices** : Tableaux 2D de nombres
- **Factorisation** : Décomposition en produit de matrices
- Matrice diagonale

### 4. Singular Value Decomposition (SVD)
- **Décomposition** : R = U × Σ × V^T
  - U : Matrice utilisateurs
  - Σ : Valeurs singulières (diagonale)
  - V^T : Matrice items (transposée)
- **Réduction** : Garder les k plus grandes valeurs singulières
- **Prédiction de rating** : Produit des matrices réduites

### 5. Problèmes et solutions
- **Problème des zéros** : Distinction entre "pas vu" et "pas aimé"
- **Solution par imputation** : Remplir avec moyennes
- **Baseline predictors** : Prendre en compte les biais
  - Biais utilisateur (note plus haut/bas que moyenne)
  - Biais item (films généralement bien/mal notés)
- **Temporal dynamics** : Évolution dans le temps

### 6. Folding-in de nouveaux utilisateurs
- Ajouter un utilisateur sans recalculer toute la SVD
- Projection dans l'espace latent existant

### 7. Recommandations avec SVD
- Calcul des scores prédits pour tous les items
- Tri par score décroissant
- Filtrage des items déjà vus

### 8. Funk SVD (Simon Funk)
- Alternative à la SVD classique
- **Avantages** :
  - Pas besoin d'imputation
  - Plus flexible
  - Meilleure performance Netflix Prize
- **Principe** : Minimiser l'erreur de prédiction
- **Formule** : r̂_ui = μ + b_u + b_i + p_u · q_i
  - μ : rating moyen global
  - b_u : biais utilisateur
  - b_i : biais item
  - p_u : vecteur facteurs utilisateur
  - q_i : vecteur facteurs item

### 9. Entraînement Funk SVD
- **Stochastic Gradient Descent (SGD)** :
  - Calcul de l'erreur : e_ui = r_ui - r̂_ui
  - Mise à jour des paramètres :
    - p_u ← p_u + α(e_ui · q_i - λ · p_u)
    - q_i ← q_i + α(e_ui · p_u - λ · q_i)
    - b_u ← b_u + α(e_ui - λ · b_u)
    - b_i ← b_i + α(e_ui - λ · b_i)
  - α : learning rate
  - λ : regularization factor

### 10. Implémentation MovieGEEKs
- Initialisation aléatoire des facteurs
- Boucle d'entraînement sur les ratings
- Calcul RMSE pour évaluation
- Génération de recommandations :
  - Brute force (tous les items)
  - Neighborhoods (items similaires)

### 11. Métriques d'évaluation
- **RMSE** (Root Mean Squared Error) : Erreur de prédiction
- Comparaison avec baseline

### 4. Types d'évaluation

### 5. Évaluation Offline
- **Préparation des données** :
  - Split des données (train/test)
  - Méthodes de split :
    - **Random split** : Aléatoire
    - **Time split** : Temporel (respecte l'ordre chronologique)
    - **User split** : Par utilisateur
  - **Stratified sampling** : Maintenir la distribution

  - **Training** : Entraînement du modèle
  - **Validation** : Tuning des hyperparamètres
  - **Test** : Évaluation finale

### 6. Métriques de prédiction (Error Metrics)
- **RMSE** (Root Mean Squared Error) :
  - Mesure l'erreur de prédiction de rating
  - Pénalise fortement les grandes erreurs
- **MAE** (Mean Absolute Error) :
  - Erreur absolue moyenne
  - Plus robuste aux outliers

### 7. Métriques de décision (Decision-Support Metrics)
- **Precision** : Proportion de recommandations pertinentes
  - Precision = TP / (TP + FP)
- **Recall** : Proportion d'items pertinents recommandés
  - Recall = TP / (TP + FN)
- **F1-Score** : Moyenne harmonique de Precision et Recall
- **Confusion Matrix** :
  - TP (True Positive) : Recommandé et pertinent
  - FP (False Positive) : Recommandé mais non pertinent
  - TN (True Negative) : Non recommandé et non pertinent
  - FN (False Negative) : Non recommandé mais pertinent

### 8. Métriques de ranking
- **MAP** (Mean Average Precision) :
  - Prend en compte l'ordre des recommandations
  - Moyenne des Precision@k pour tous les utilisateurs
- **DCG** (Discounted Cumulative Gain) :
  - Gain cumulé avec dévaluation par position
- **NDCG** (Normalized DCG) :
  - DCG normalisé par l'idéal

## 📚 PDF 10 - Approches Hybrides

### 1. Types de recommenders hybrides
- **Monolithic** : Combine des composants de différents algorithmes
- **Mixed** : Empile plusieurs recommandations
- **Ensemble** : Combine les prédictions de plusieurs modèles

### 2. Monolithic Hybrid
- **Principe** : Mix de composants d'algorithmes différents
- **Exemple** :
  - Similarité d'items de Recommender 1
  - Sélection de candidats de Recommender 2
  - Prédiction de ratings de Recommender 2
- **Cas d'usage** : Ajouter features content-based au CF

### 3. Amélioration CF avec features content
- Ajout de pseudo-users pour chaque genre/catégorie
- Ces pseudo-users "aiment" tous les items de leur catégorie
- Permet de connecter des items similaires sans overlap d'utilisateurs
- Résout partiellement le cold start

### 4. Mixed Hybrid
- **Principe** : Stacking simple des résultats
- **Ordre** : Du plus personnalisé au moins personnalisé
  1. Recommender le plus personnalisé
  2. Recommender moyennement personnalisé
  3. Popularity recommender (fallback)
- Assure toujours des recommandations même pour cold start

### 5. Ensemble Recommenders
- **Définition** : Combinaison de prédictions de plusieurs modèles
- **Avantage** : Souvent meilleures performances que modèle seul
- **Conseil RecSys 2016** : Commencer avec Matrix Factorization puis ajouter des ensembles

### 6. Switched Ensemble
- **Principe** : Utiliser le meilleur outil pour chaque situation
- **Exemple** :
  - CF pour utilisateurs avec historique
  - Content-based pour nouveaux items
  - Popularity pour cold users
- Basculement selon critères (nombre de ratings, confiance, etc.)

### 7. Weighted Ensemble
- **Principe** : Moyenne pondérée des prédictions
- **Formule** : r̂ = w₁·r̂₁ + w₂·r̂₂ + ... + wₙ·r̂ₙ
- **Détermination des poids** :
  - Expertise domaine
  - Apprentissage automatique
  - Performance historique

### 8. Feature-Weighted Linear Stacking (FWLS)
- **Méthode gagnante Netflix Prize**
- **Principe** :
  1. Entraîner plusieurs recommenders
  2. Créer des meta-features pour chaque paire (user, item)
  3. Utiliser régression linéaire pour combiner
  
- **Meta-features** :
  - Prédictions de chaque recommender
  - Fonctions des features : F₁(u,i), F₂(u,i), etc.
  - Produits : Prediction_CF × F₁, Prediction_CB × F₂
  
- **Training FWLS** :
  1. Exécuter chaque recommender sur training data
  2. Calculer meta-features pour chaque point
  3. Régression linéaire pour trouver les poids optimaux
  4. Tester sur test set

- **Exemple MovieGEEKs** :
  - Collaborative Filtering
  - Content-Based
  - Meta-features : nombre de ratings user, popularité item

### 9. Linear Regression pour FWLS
- **Objectif** : Minimiser l'erreur carrée
- **Similar à Funk SVD** : Gradient descent
- **Trouve les poids v** optimaux

### 10. Avantages des Hybrides
- Combine les forces de chaque approche
- Atténue les faiblesses individuelles
- Meilleure robustesse
- Performance généralement supérieure

### 11. Cas Netflix Prize
- Ensemble extrêmement complexe
- Combinait des centaines de modèles
- 10% d'amélioration atteint
- Jamais mis en production (trop complexe)
