## 1. 🤝 Qu'est-ce que le Collaborative Filtering ? {#definition}

### Définition

**Collaborative Filtering (Filtrage Collaboratif)** est une technique de recommandation basée sur l'idée que :

> **"Les utilisateurs similaires en termes d'historique d'interactions sont considérés comme ayant des goûts similaires et sont susceptibles de partager des préférences similaires dans le futur."**

### Idée Générale

```
Utilisateurs similaires → Goûts similaires → Préférences futures similaires
```

**En d'autres termes :**
- Si Alice et Bob ont aimé les mêmes films dans le passé
- Et Alice a aimé un nouveau film X
- Alors Bob aimera probablement aussi le film X

---

### Caractéristiques Clés

**✅ Ce que CF utilise :**
- **Historique des interactions utilisateur-item** (ratings, clics, achats, etc.)
- **Comportement passé d'utilisateurs similaires**
- **Patterns collectifs** dans les données

**❌ Ce que CF n'utilise PAS :**
- **Aucune information supplémentaire sur les items** (pas besoin de métadonnées)
- Pas de description de contenu
- Pas de features explicites (genre, acteur, etc.)

> **Point fort :** CF peut découvrir des associations **non évidentes** que le content-based ne pourrait pas trouver.

---

### Exemple Illustratif

```
Alice aime : [Star Wars, Matrix, Inception]
Bob aime   : [Star Wars, Matrix, Inception]
Carol aime : [Titanic, The Notebook, Pride & Prejudice]

Alice vient de regarder et aimer : Interstellar

Collaborative Filtering → Recommander Interstellar à Bob
                        → Ne PAS recommander à Carol
```

**Pourquoi ?**
- Alice et Bob ont des **profils similaires** (même historique)
- Carol a un profil **différent** (préférences romantiques)
- CF détecte ces patterns sans connaître le contenu des films

---

## 2. 🧠 Principe Général {#principe}

### Hypothèses Fondamentales

Le Collaborative Filtering repose sur **3 hypothèses** :

#### 1. **Similarité des goûts**
> Utilisateurs avec historique similaire → Préférences similaires

#### 2. **Stabilité temporelle**
> Les préférences restent relativement **stables dans le temps**
> (du moins à court/moyen terme)

#### 3. **Transitivité des préférences**
> Si A ressemble à B, et B ressemble à C
> Alors il y a une chance que A ressemble à C

---

### Comment ça marche ?

**Pipeline général :**

```
┌─────────────────────────────────────────────────┐
│  1. Collecter interactions utilisateur-item     │
│     (feedback matrix)                           │
└──────────────────┬──────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────┐
│  2. Calculer similarités                        │
│     (entre users OU entre items)                │
└──────────────────┬──────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────┐
│  3. Identifier voisinage (neighbors)            │
│     (k utilisateurs/items les plus similaires)  │
└──────────────────┬──────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────┐
│  4. Prédire ratings / Générer recommandations   │
│     (basé sur voisinage et interactions passées)│
└─────────────────────────────────────────────────┘
```

---

### Limitations Importantes

**⚠️ Cependant, CF a des contraintes :**

1. **Nécessite un grand nombre d'interactions utilisateurs**
   - Beaucoup de données nécessaires
   - Sparsité problématique

2. **Nécessite que les produits soient standardisés**
   - Items doivent être comparables
   - Difficile pour items uniques ou hautement personnalisables

3. **Assume que le comportement passé détermine le comportement actuel**
   - Ne capture pas changements de goût
   - Biais vers historique

---

## 3. 📂 Catégories d'Approches {#categories}

Il existe **deux grandes catégories** d'approches en Collaborative Filtering :

### 3.1 Memory-Based Approaches (Basées sur la Mémoire)

**Principe :**
> Utiliser **directement** les interactions enregistrées pour calculer recommandations

**Caractéristiques :**
- Pas d'apprentissage de modèle
- Calculs à la volée
- Utilise toute la matrice de ratings

**Types :**
- **User-based** : Trouver utilisateurs similaires
- **Item-based** : Trouver items similaires

**Exemple typique :** k-Nearest Neighbors (k-NN)

---

### 3.2 Model-Based Approaches (Basées sur un Modèle)

**Principe :**
> **Apprendre un modèle prédictif** qui est ensuite utilisé pour recommandations

**Caractéristiques :**
- Phase d'apprentissage (training)
- Modèle compact (pas besoin de toute la matrice)
- Prédictions rapides

**Exemple typique :** Matrix Factorization (SVD, ALS, NMF)

---

### Comparaison Visuelle

```
┌─────────────────────────────────────────────────┐
│           MEMORY-BASED                          │
├─────────────────────────────────────────────────┤
│  Données brutes → Calcul direct → Recommandation│
│                                                  │
│  + Simple, interprétable                        │
│  - Lent sur grandes données                     │
│  - Nécessite toute la matrice                   │
└─────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────┐
│            MODEL-BASED                          │
├─────────────────────────────────────────────────┤
│  Données → Training → Modèle → Recommandation   │
│                                                  │
│  + Rapide (après training)                      │
│  + Scalable                                     │
│  - Moins interprétable                          │
│  - Nécessite phase d'apprentissage              │
└─────────────────────────────────────────────────┘
```

## 4. 💾 Memory-Based Approaches {#memory-based}

### 4.1 Idée Générale du Neighborhood-Based

**Deux variantes possibles :**

1. **Utilisateurs similaires** sont intéressés par les **mêmes items**
   → User-based CF

2. **Items similaires** intéressent les **mêmes utilisateurs**
   → Item-based CF

**Assumption commune :**
> Les préférences utilisateurs restent **stables dans le temps**

---

### 4.2 Composants d'une Approche k-NN

**k-Nearest Neighbor (k-NN) approach** comprend **2 étapes** :

#### Étape 1 : Déterminer les voisins (Neighbors)

**Objectif :** Identifier les k entités les plus similaires

**Pour User-based :**
```
Target user → Trouver k utilisateurs les plus similaires
```

**Pour Item-based :**
```
Target item → Trouver k items les plus similaires
```

**Comment ?** Utiliser une **mesure de similarité**

---

#### Étape 2 : Calculer scores de pertinence

**Objectif :** Prédire rating ou générer recommandations

**Basé sur :**
- Les **voisins** identifiés (étape 1)
- Les **interactions passées** de ces voisins

**Formule générale (simplifiée) :**
```
Score(user, item) = f(neighbors, past_interactions)
```

---

## 5. 🏘️ Item-Based Neighborhood Approach {#item-based}

### 5.1 Vue d'Ensemble

L'**Item-Based Collaborative Filtering** est généralement **plus stable** et **performant** que User-Based.

**Pourquoi ?**
> **Les relations entre items sont plus stables que les relations entre utilisateurs**

**Exemple :**
- "Star Wars" et "Matrix" resteront similaires dans le temps
- Mais les goûts d'Alice peuvent changer

---

### 5.2 Processus Détaillé

#### Exemple avec Matrice de Ratings

**Matrice initiale :**

```
          🎬      🎬       🎬      🎬         🎬        🎬
        Barbie Anatomy   Wonka   Film4    Marvels  Migration
       ┌──────────────────────────────────────────────────┐
😊 U1  │   4              5       1                       │
😊 U2  │                          5        4        3     │
😊 U3  │          3       1       5                       │
😊 U4  │   2      2                        5        4     │ ← Target
😊 U5  │          5               2                       │
       └──────────────────────────────────────────────────┘
```

**Target User (U4) :**
- A noté : Barbie (2), Anatomy (2), Marvels (5), Migration (4)
- N'a PAS noté : Wonka, Film4
- **Objectif** : Prédire ratings pour Wonka et Film4

---

### 5.3 Étape 1 : Calculer Similarités entre Items

**Construire matrice de similarité item-item :**

```
              🎬        🎬        🎬       🎬         🎬        🎬
           Barbie   Anatomy    Wonka    Film4    Marvels  Migration
         ┌────────────────────────────────────────────────────────┐
Barbie   │   1.0                                                   │
Anatomy  │         1.0                                             │
Wonka    │                    1.0                                  │
Film4    │                             1.0                         │
Marvels  │                                        1.0              │
Migration│                                                  1.0    │
         └────────────────────────────────────────────────────────┘
```

**Calcul avec mesure de similarité** (ex: Cosine, Jaccard, Pearson)

---

### 5.4 Étape 2 : Sélectionner k Neighbors

**Pour chaque item non noté**, trouver les **k items les plus similaires** parmi ceux **déjà notés** par l'utilisateur.

**Exemple pour prédire rating de U4 sur Wonka :**

```
Items notés par U4 : [Barbie(2), Anatomy(2), Marvels(5), Migration(4)]

Similarités avec Wonka :
- sim(Wonka, Barbie) = 0.7
- sim(Wonka, Anatomy) = 0.3
- sim(Wonka, Marvels) = 0.1
- sim(Wonka, Migration) = 0.6

Sélection k=2 neighbors :
→ Barbie (sim = 0.7)
→ Migration (sim = 0.6)
```

---

### 5.5 Étape 3 : Calculer Score de Pertinence

**Formule de prédiction :**

```
         Σ sim(i, j) × r_uj
         j∈ℬ(i)
r̂_ui = ─────────────────────
           Σ sim(i, j)
         j∈ℬ(i)
```

**Où :**
- **r̂_ui** : Rating prédit de user u pour item i
- **ℬ(i)** : Ensemble des k voisins de l'item i (notés par user u)
- **sim(i,j)** : Similarité entre items i et j
- **r_uj** : Rating de user u pour item j (voisin)

---

### 5.6 Exemple de Calcul

**Prédire r̂_U4,Wonka avec k=2 neighbors : [Barbie, Migration]**

```
Données :
- r_U4,Barbie = 2,    sim(Wonka, Barbie) = 0.7
- r_U4,Migration = 4, sim(Wonka, Migration) = 0.6

Calcul :
Numérateur = (0.7 × 2) + (0.6 × 4) = 1.4 + 2.4 = 3.8
Dénominateur = 0.7 + 0.6 = 1.3

r̂_U4,Wonka = 3.8 / 1.3 ≈ 2.9
```

**Interprétation :** U4 devrait noter Wonka environ **2.9/5**

---

### 5.7 Génération de Recommandations

**Après calcul des prédictions pour tous items non notés :**

```
User U4 - Ratings finaux :

         Original  Prédit
       ┌─────────────────┐
Barbie │    2             │
Anatomy│    2             │
Wonka  │         →  2.9   │
Film4  │         →  3.5   │
Marvels│    5             │
Migr.  │    4             │
       └─────────────────┘

Recommandation Top-2 (items non vus) :
1. Film4 (score: 3.5)
2. Wonka (score: 2.9)
```

## 6. 📏 Mesures de Similarité {#similarity}

### 6.1 Jaccard Similarity

**Pour données binaires** (vu/pas vu)

**Formule :**
```
sim_JS(u, v) = |ℐ_u ∩ ℐ_v| / |ℐ_u ∪ ℐ_v|
```

**Exemple :**

```
          🎬      🎬       🎬      🎬       🎬        🎬
        Barbie Anatomy  Wonka   Film4   Marvels  Migration   JS
       ┌────────────────────────────────────────────────────────┐
😊 U1  │   4              5       1                            │ 0.16
😊 U2  │                          5       4        3           │ 0.75
😊 U3  │          3       1       5                            │ 0.16
Target │                                                        │
😊 U4  │   2      2                       5        4           │
😊 U5  │          5               2                            │ 0.4
       └────────────────────────────────────────────────────────┘

Calcul JS(U4, U2) :
ℐ_U4 = {Barbie, Anatomy, Marvels, Migration}
ℐ_U2 = {Film4, Marvels, Migration}

ℐ_U4 ∩ ℐ_U2 = {Marvels, Migration} → |∩| = 2
ℐ_U4 ∪ ℐ_U2 = {Barbie, Anatomy, Film4, Marvels, Migration} → |∪| = 5

JS = 2/5 = 0.4 ... Wait, slide dit 0.75 🤔
```

*Note : Vérifier calcul avec données slides*

---

### 6.2 Cosine Similarity

**Pour vecteurs de ratings**

**Formule :**
```
sim_CS(u, v) = (r_u^T · r_v^T) / (||r_u|| × ||r_v||)
```

**Interprétation géométrique :**
- Calcule le **cosinus de l'angle** entre deux vecteurs
- Varie entre 0 (orthogonal) et 1 (colinéaire)

**Exemple visuel :**

```
        Rating Film2
            ↑
          5 │      😊 (User 5)
            │     /
          4 │    /
            │   /
          3 │  / 📐
            │ /
          2 │/___________😊 (User 1)
            /    😊 😊
          1/    (Target & U3)
           ────────────────→
              Rating Film1
```

**Caractéristique :**
- Ignore la magnitude (moyenne des ratings)
- Focus sur la **direction** (pattern de préférences)

---

### 6.3 Pearson Correlation

**Pour capturer corrélation linéaire** (avec centrage)

**Formule :**
```
         Σ (r_ux - r̄_u)(r_vx - r̄_v)
         x∈ℐ_uv
sim_PC(u,v) = ─────────────────────────────────
              √[Σ(r_ux-r̄_u)²] √[Σ(r_vx-r̄_v)²]
```

**Caractéristiques :**
- Centre les ratings autour de la moyenne de chaque utilisateur
- Gère les **biais utilisateurs** (certains notent toujours haut/bas)
- Varie entre -1 (anti-corrélé) et +1 (fortement corrélé)

**Visualisation :**

```
Graph montrant patterns de ratings de différents users
(Voir slide 7 pour visualisation complète)
```

**Avantage :** Capture les **tendances** plutôt que valeurs absolues

## 7. ⚖️ User-Based vs Item-Based {#comparison}

### 7.1 Différences Fondamentales

| Aspect | User-Based CF | Item-Based CF |
|--------|---------------|---------------|
| **Similarité calculée** | Entre utilisateurs | Entre items |
| **Question posée** | "Quels users me ressemblent ?" | "Quels items se ressemblent ?" |
| **Stabilité** | ⚠️ Faible (goûts changent) | ✅ Élevée (items stables) |
| **Scalabilité** | ❌ Difficile (beaucoup de users) | ✅ Meilleure (moins d'items) |
| **Performance** | ⭐⭐ Moyenne | ⭐⭐⭐ Généralement supérieure |

---

### 7.2 Pourquoi Item-Based est souvent meilleur ?

**Raison principale :**
> **Les relations entre items sont plus stables que les relations entre utilisateurs**

**Explications :**

1. **Stabilité temporelle**
   ```
   Items : "Star Wars" ≈ "Matrix" (toujours vrai)
   Users : Alice_2020 ≠ Alice_2025 (peut changer)
   ```

2. **Nombre d'entités**
   - Souvent : #Users >> #Items
   - Calcul similarités items plus gérable

3. **Sparsité**
   - Item-item : Plus de co-occurrences
   - User-user : Moins de chevauchement

---

### 7.3 Architecture Offline/Online

**Composante Offline (pré-calcul) :**
```
Calculer similarités entre items
→ Peut être fait périodiquement (ex: nightly batch)
→ Résultat : Matrice similarité item-item
```

**Composante Online (temps réel) :**
```
User visite → Récupérer items notés → Lookup similarités → Générer recs
→ Très rapide (pas de calcul intensif)
```

**Avantage :** Prédictions et recommandations **rapides** en production

## 8. ✅❌ Avantages et Inconvénients {#pros-cons}

### 8.1 Avantages du CF (Memory-Based)

**✅ Pros :**

1. **Simple et intuitif**
   - Facile à comprendre et implémenter
   - Un seul paramètre à tuner : k (nombre de voisins)

2. **Facilement explicable**
   - "Recommandé car utilisateurs similaires ont aimé"
   - Transparence pour l'utilisateur

3. **Pas besoin de métadonnées items**
   - Fonctionne uniquement avec interactions
   - Découvre patterns cachés

4. **Serendipity potentielle**
   - Peut recommander items non-évidents
   - Basé sur comportements collectifs

---

### 8.2 Inconvénients du CF (Memory-Based)

**❌ Cons :**

1. **Scalability issues**
   - Calcul du voisinage coûteux
   - Complexité O(n²) pour similarités

2. **Manque de sensibilité à la sparsité**
   - Performance dégradée avec données sparses
   - Besoin de beaucoup d'interactions

3. **Performance généralement inférieure aux model-based**
   - Pas d'apprentissage de patterns latents
   - Limité par données brutes

4. **Cold start**
   - Nouveaux users : pas d'historique
   - Nouveaux items : pas d'interactions

5. **Popularity bias**
   - Tend à sur-recommander items populaires
   - Long tail ignoré

## Conclusion

Le **Collaborative Filtering Memory-Based** est :

✅ Une approche **intuitive et explicable**  
✅ Particulièrement efficace en **Item-Based CF**  
✅ **Simple à implémenter** avec un seul hyperparamètre (k)  

Mais souffre de :
❌ Problèmes de **scalabilité**  
❌ **Sensibilité à la sparsité**  
❌ Performance souvent **inférieure aux approches model-based**  

**Prochaine étape :** Approches **Model-Based** (Matrix Factorization) qui résolvent plusieurs de ces limitations ! 🚀
