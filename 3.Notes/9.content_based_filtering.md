# Content-Based Filtering - Guide Complet

## 1. Introduction au Content-Based Filtering

### Principe fondamental
Le **filtrage basé sur le contenu** (Content-Based Filtering) utilise les **informations de contenu** sur les utilisateurs et les items pour générer des recommandations, plutôt que de se baser sur les interactions et préférences des autres utilisateurs.

### Approche principale
Recommander des items qui sont **similaires** à ceux avec lesquels l'utilisateur a précédemment interagi.

---

## 2. Architecture d'un Système Content-Based

Un système de recommandation basé sur le contenu se compose de trois modules principaux :

### 2.1 Content Analyzer (Analyseur de contenu)
**Rôle** : Extraire des informations sur le contenu des items

**Fonctions** :
- Construire des **profils d'items**
- Extraire les caractéristiques pertinentes
- Transformer le contenu brut en représentation exploitable

### 2.2 User Profiler (Profileur utilisateur)
**Rôle** : Construire des profils utilisateurs basés sur leurs préférences

**Fonctions** :
- Agréger les profils des items avec lesquels l'utilisateur a interagi
- Créer une représentation de l'utilisateur dans le même espace que les items
- Mettre à jour les préférences au fil du temps

### 2.3 Item Retriever (Récupérateur d'items)
**Rôle** : Filtrer et recommander les items

**Fonctions** :
- Calculer les **similarités** entre profils utilisateur et profils d'items
- Classer les items selon leur pertinence
- Générer la liste de recommandations

---

## 3. Types de Contenu d'un Item

### 3.1 Features ou Caractéristiques explicites
**Description** : Attributs structurés et définis de l'item

**Exemples** :
- Genre d'un film (action, comédie, drame)
- Catégorie d'un produit
- Année de sortie
- Durée
- Prix

### 3.2 Contenu textuel
**Description** : Informations non structurées sous forme de texte

**Sources** :
- Titre
- Description
- Synopsis
- Tags
- Commentaires

**Traitement** : Utilisation de techniques NLP (Natural Language Processing)

### 3.3 Features extraites du signal
**Description** : Caractéristiques extraites de données multimédia

**Types** :
- **Images** : couleurs dominantes, textures, formes, objets détectés
- **Audio** : tempo, tonalité, instruments, genre musical
- **Vidéo** : scènes, mouvements, visages

## 4. Construction des Profils d'Items

### 4.1 Vector Space Model (VSM)

Le **Modèle d'Espace Vectoriel** est la méthode principale pour représenter le contenu textuel.

#### Principe
- Représentation **spatiale** des documents textuels
- Chaque document devient un vecteur dans un espace multidimensionnel
- Chaque dimension correspond à un **terme du vocabulaire**

#### Visualisation
```
         term_2
            ↑
            |    Item A
            |   /
            |  /
            | /
            |/________→ term_1
           /|
          / |
         /  |
    Item C  |
            | Item B
       term_n
```

### 4.2 Extraction des Features Textuelles

**Techniques NLP utilisées** :
1. **Tokenization** : découpage du texte en mots (tokens)
2. **Normalization** : mise en minuscules, suppression de la ponctuation
3. **Stemming** : réduction des mots à leur racine (ex: "running" → "run")
4. **Stop words removal** : suppression des mots courants ("le", "la", "de", etc.)

### 4.3 Pondération TF-IDF

**TF-IDF** = Term Frequency × Inverse Document Frequency

#### Formules

**Term Frequency (TF)** :
```
TF_w,d_i = f_w,d_i / max_{w'∈d_i} f_{w',d_i}
```
Où :
- `f_w,d_i` : nombre d'occurrences du mot w dans le document d_i
- Le dénominateur normalise par la fréquence maximale dans le document

**Inverse Document Frequency (IDF)** :
```
IDF_w,d_i = log(|I| / |{i ∈ I : w ∈ d_i}|)
```
Où :
- `|I|` : nombre total de documents
- `|{i ∈ I : w ∈ d_i}|` : nombre de documents contenant le mot w

**TF-IDF final** :
```
TF-IDF_w,d_i = TF_w,d_i × IDF_w,d_i
```

#### Interprétation

**TF (Term Frequency)** :
- Mesure l'importance d'un terme **dans un document spécifique**
- Plus le terme apparaît souvent, plus son TF est élevé
- Normalisé pour éviter de favoriser les longs documents

**IDF (Inverse Document Frequency)** :
- Mesure la **rareté** d'un terme dans l'ensemble du corpus
- Les termes rares ont un IDF élevé
- Les termes communs (présents partout) ont un IDF faible

**TF-IDF combiné** :
- Favorise les termes **fréquents dans le document** mais **rares dans le corpus**
- Pénalise les mots trop communs ou trop rares
- Identifie les mots vraiment caractéristiques d'un document

#### Exemple pratique

Considérons 3 films :
- Film A : "Un film d'action avec des explosions spectaculaires"
- Film B : "Une comédie romantique avec des personnages attachants"
- Film C : "Un film d'action bourré d'adrénaline"

Pour le mot "action" dans le Film A :
- **TF** : élevé (le mot apparaît dans le film)
- **IDF** : moyen (le mot apparaît dans 2 films sur 3)
- **TF-IDF** : moyen

Pour le mot "explosions" dans le Film A :
- **TF** : élevé (le mot apparaît dans le film)
- **IDF** : élevé (le mot n'apparaît que dans 1 film sur 3)
- **TF-IDF** : élevé ✓ (terme discriminant)

Pour le mot "film" :
- **TF** : élevé partout
- **IDF** : faible (apparaît dans tous les films)
- **TF-IDF** : faible (pas discriminant)

## 5. Construction des Profils Utilisateurs

### 5.1 Principe

Les **profils utilisateurs** indiquent l'intérêt de l'utilisateur dans les différentes dimensions des items.

**Caractéristiques** :
- Créés dans le **même espace vectoriel** que les profils d'items
- Permettent la comparaison directe entre utilisateurs et items
- Évoluent avec le temps selon les nouvelles interactions

### 5.2 Méthode d'Estimation

Le profil utilisateur peut être obtenu en **agrégeant** les profils des items avec lesquels l'utilisateur a interagi.

**Approches possibles** :
1. **Moyenne simple** : profil_user = moyenne(profils_items_aimés)
2. **Moyenne pondérée** : selon les notes données aux items
3. **Somme normalisée** : accumulation des caractéristiques
4. **Décroissance temporelle** : donner plus de poids aux interactions récentes

### 5.3 Exemple

Si un utilisateur a aimé :
- Item A : [0.8 (action), 0.2 (comédie), 0.1 (romance)]
- Item B : [0.7 (action), 0.3 (sci-fi), 0.0 (romance)]
- Item C : [0.5 (action), 0.0 (comédie), 0.4 (drame)]

Son profil pourrait être :
```
Profil_user = [0.67 (action), 0.17 (comédie), 0.10 (sci-fi), 0.17 (romance), 0.13 (drame)]
```

## 6. Mesure de Similarité et Prédiction

### 6.1 Calcul de Similarité

Pour prédire l'intérêt d'un utilisateur pour un item, on calcule la **similarité** entre leurs profils.

**Similarité cosinus** (la plus courante) :
```
sim(user, item) = cos(θ) = (profil_user · profil_item) / (||profil_user|| × ||profil_item||)
```

**Interprétation** :
- Valeur entre -1 et 1 (ou 0 et 1 pour des vecteurs positifs)
- Plus la valeur est élevée, plus l'item correspond aux préférences de l'utilisateur

### 6.2 Génération de Recommandations

**Processus** :
1. Calculer la similarité entre le profil utilisateur et tous les items candidats
2. Classer les items par similarité décroissante
3. Filtrer les items déjà consommés
4. Retourner les top-N items

## 7. Autres Techniques pour le Content-Based

Au-delà de TF-IDF et similarité cosinus, d'autres approches peuvent être utilisées :

### 7.1 Machine Learning Classique
- **Naive Bayes** : classification probabiliste des préférences
- **Decision Trees** : règles de décision sur les features
- **Clustering** : regroupement d'items similaires

### 7.2 Deep Learning
- **Neural Networks** : apprentissage de représentations complexes
- **Embeddings** : représentations denses des items et utilisateurs
- **CNN** : pour l'extraction de features d'images
- **RNN/Transformers** : pour le traitement de textes et séquences

## 8. Avantages et Inconvénients

### 8.1 Avantages (Pros)

#### Item Cold-Start
**✓ Capacité à recommander des items nouveaux et impopulaires**
- Pas besoin d'historique d'interactions
- Seul le contenu de l'item est nécessaire
- Résout le problème du cold-start pour les items

#### Explicabilité
**✓ Possibilité d'expliquer les recommandations**
- On peut identifier les features qui ont conduit à la recommandation
- Transparence pour l'utilisateur
- Exemple : "Recommandé car vous aimez les films d'action"

### 8.2 Inconvénients (Cons)

#### Disponibilité du Contenu
**✗ Performance liée à la qualité et disponibilité du contenu**
- Nécessite des métadonnées riches et de qualité
- Difficile pour certains types d'items (musique abstraite, art)
- Coût d'extraction et de maintenance du contenu

#### Surspécialisation (Overspecialization)
**✗ Incapacité à fournir des recommandations nouvelles ou inattendues**
- L'utilisateur reçoit toujours des items similaires à ce qu'il connaît
- Manque de sérendipité (découvertes surprenantes)
- Risque de bulle de filtrage
- Pas de diversité dans les recommandations

#### User Cold-Start
**✗ Nécessite de collecter suffisamment d'interactions utilisateur**
- Profil utilisateur vide au début
- Difficulté à recommander pour les nouveaux utilisateurs
- Nécessite une phase d'apprentissage

## 9. Comparaison Collaborative vs Content-Based

| Aspect | Collaborative Filtering | Content-Based Filtering |
|--------|------------------------|------------------------|
| **Données utilisées** | Interactions utilisateurs | Contenu des items |
| **Item cold-start** | ✗ Problématique | ✓ Géré naturellement |
| **User cold-start** | ✗ Problématique | ✗ Problématique |
| **Diversité** | ✓ Bonnes découvertes | ✗ Surspécialisation |
| **Explicabilité** | ✗ Difficile | ✓ Facile |
| **Sérendipité** | ✓ Élevée | ✗ Faible |
| **Qualité contenu** | Non nécessaire | ✓ Critique |

## 10. Bonnes Pratiques

### 10.1 Preprocessing du Contenu
- Nettoyer et normaliser les données textuelles
- Choisir judicieusement le vocabulaire (supprimer stop words)
- Gérer les synonymes et variantes

### 10.2 Feature Engineering
- Combiner features textuelles et structurées
- Utiliser des embeddings pré-entraînés (Word2Vec, BERT) pour de meilleures représentations
- Tester différentes pondérations

### 10.3 Évolution du Profil Utilisateur
- Mettre à jour régulièrement selon les nouvelles interactions
- Considérer la temporalité (préférences récentes vs anciennes)
- Gérer l'évolution des goûts

### 10.4 Diversification
- Introduire de la randomisation dans les recommandations
- Pénaliser les items trop similaires entre eux
- Combiner avec d'autres approches (hybridation)

---

## 11. Résumé des Concepts Clés

1. **Content-Based Filtering** recommande en se basant sur la similarité de contenu
2. **TF-IDF** est la méthode standard pour représenter du texte
3. Les **profils utilisateurs** sont construits à partir des items consommés
4. La **similarité cosinus** est utilisée pour mesurer la correspondance
5. **Avantages** : pas de item cold-start, explicabilité
6. **Inconvénients** : surspécialisation, dépendance à la qualité du contenu
7. Souvent combiné avec le collaborative filtering dans des **systèmes hybrides**

---

## 12. Pour Aller Plus Loin

### Techniques Avancées
- **Semantic Analysis** : comprendre le sens profond des textes
- **Knowledge Graphs** : représentations structurées de connaissances
- **Multi-modal Learning** : combiner texte, images, audio
- **Contextual Bandits** : apprentissage en ligne des préférences

### Systèmes Hybrides
Combiner content-based et collaborative filtering pour :
- Compenser les faiblesses de chaque approche
- Améliorer la qualité globale des recommandations
- Offrir diversité ET pertinence
