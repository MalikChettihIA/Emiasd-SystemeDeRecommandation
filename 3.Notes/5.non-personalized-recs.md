## 1. 🎯 Introduction : Personnalisé vs Non-Personnalisé {#intro}

### 1.1 Recommandations Personnalisées (Personalized)

**Définition :**
> Adapter la liste de recommandations à un **individu spécifique**.

**Caractéristiques :**
- 📊 Utilise **informations sur l'utilisateur cible** :
  - Historique d'interactions
  - Profil démographique
  - Préférences explicites
  - Comportement passé
  
- 👥 Utilise **informations sur utilisateurs similaires** :
  - Collaborative Filtering
  - Similarités comportementales
  - Patterns de consommation

**Exemples :**
```
User A (fan de SF) → [Dune, Interstellar, Arrival]
User B (fan de comédie) → [Superbad, The Hangover, Bridesmaids]
```

**Avantages :**
- ✅ Haute pertinence pour l'utilisateur
- ✅ Découverte personnalisée
- ✅ Meilleur engagement

**Inconvénients :**
- ❌ Nécessite données utilisateur
- ❌ Cold-start problem
- ❌ Complexité algorithmique

---

### 1.2 Recommandations Non-Personnalisées (Non-Personalized)

**Définition :**
> Recommandations qui **ne nécessitent aucune connaissance** sur l'utilisateur individuel.

**Caractéristiques :**
- 🌍 Utilise **informations agrégées** sur tous les utilisateurs :
  - Popularité globale
  - Tendances générales
  - Patterns collectifs
  
- 🚫 **Aucune personnalisation** :
  - Mêmes recommandations pour tous
  - Pas d'historique nécessaire
  - Approche "one-size-fits-all"

**Exemples :**
```
Tout le monde → [Avatar, Titanic, Avengers]
                (Films les plus populaires)
```

**Avantages :**
- ✅ **Simple à implémenter**
- ✅ **Pas de cold-start** : Fonctionne immédiatement
- ✅ **Rapide** : Calculs minimaux
- ✅ **Preuve sociale** : "Tout le monde aime ça"
- ✅ **Baseline** : Point de comparaison pour autres algorithmes

**Inconvénients :**
- ❌ Pas adapté aux goûts individuels
- ❌ Manque de surprise/découverte
- ❌ Popularité bias
- ❌ Utilisateurs peuvent déjà connaître

## 2. 🔗 Association Rules (Règles d'Association) {#association-rules}

### 2.1 Principe Général

**Définition :**
> Découvrir des **patterns fréquents** dans les transactions : "Les utilisateurs qui ont interagi avec X ont aussi interagi avec Y".

**Notation :**
```
Règle : i → j
"Si item i, alors item j"
```

**Exemple :**
```
Barbie → Wonka
"Les utilisateurs qui ont regardé Barbie ont aussi regardé Wonka"
```

---

### 2.2 Construction des Règles

#### Étape 1 : Matrice Utilisateur-Item

**Matrice de feedback binaire** (1 = regardé, vide = pas regardé) :

```
        🎬       🎬        🎬       🎬         🎬        🎬
      Barbie  Anatomy   Wonka    Film4    Marvels  Migration
     ┌───────────────────────────────────────────────────────┐
😊 1 │   1                 1        1                         │
😊 2 │                            1        1        1         │
😊 3 │            1        1        1                         │
😊 4 │   1        1                          1        1       │
😊 5 │            1                 1                         │
     └───────────────────────────────────────────────────────┘
```

---

#### Étape 2 : Matrice de Co-occurrence

Pour chaque paire d'items (i, j), compter combien d'utilisateurs ont interagi avec **les deux**.

**Matrice "Also watched..."** (items regardés ensemble) :

```
                  Also watched...
               🎬      🎬      🎬      🎬      🎬      🎬
           Barbie Anatomy  Wonka  Film4 Marvels Migration
           ┌──────────────────────────────────────────────┐
Users who  │
watched... │
           │
🎬 Barbie  │        1       1       1       1       1
           │
🎬 Anatomy │   1           1               1       1
           │
🎬 Wonka   │   1    1              2       0       0
           │
🎬 Film4   │   1    2       2                      1
           │
🎬 Marvels │   1    1       0       1               2
           │
🎬 Migr.   │   1    1       0       1       2
           └──────────────────────────────────────────────┘
```

**Lecture :**
- Cellule (Barbie, Wonka) = 1 → 1 utilisateur a regardé les deux
- Cellule (Film4, Anatomy) = 2 → 2 utilisateurs ont regardé les deux
- Cellule (Wonka, Marvels) = 0 → Aucun utilisateur n'a regardé les deux

---

### 2.3 Métriques d'Évaluation des Règles

#### 2.3.1 Confidence (Confiance)

**Définition :**
> Proportion d'utilisateurs ayant interagi avec i qui ont **aussi** interagi avec j.

**Formule :**
```
c(i → j) = |𝒰ᵢ ∩ 𝒰ⱼ| / |𝒰ᵢ|
```

Où :
- **𝒰ᵢ** : Ensemble des utilisateurs ayant interagi avec item i
- **𝒰ⱼ** : Ensemble des utilisateurs ayant interagi avec item j
- **𝒰ᵢ ∩ 𝒰ⱼ** : Utilisateurs ayant interagi avec **les deux**

**Interprétation :**
- "Parmi ceux qui ont aimé i, quel % a aussi aimé j ?"
- Confidence élevée → Forte association

**Exemple :**
```
Règle : Wonka → Film4

𝒰_Wonka = {User1, User3}           → |𝒰_Wonka| = 2
𝒰_Film4 = {User1, User2, User3, User5} → |𝒰_Film4| = 4
𝒰_Wonka ∩ 𝒰_Film4 = {User1, User3}  → |∩| = 2

c(Wonka → Film4) = 2 / 2 = 1.0 = 100%
```

**Conclusion :** Tous ceux qui ont regardé Wonka ont aussi regardé Film4 !

---

#### 2.3.2 Support

**Définition :**
> Proportion d'utilisateurs ayant interagi avec **les deux** items i et j.

**Formule :**
```
S(i → j) = |𝒰ᵢ ∩ 𝒰ⱼ| / |𝒰|
```

Où :
- **𝒰** : Ensemble total des utilisateurs
- **|𝒰|** : Nombre total d'utilisateurs

**Interprétation :**
- "Quelle fraction de la population a interagi avec i ET j ?"
- Support élevé → Pattern fréquent dans la population

**Exemple :**
```
Règle : Wonka → Film4

|𝒰| = 5 utilisateurs au total
|𝒰_Wonka ∩ 𝒰_Film4| = 2

S(Wonka → Film4) = 2 / 5 = 0.4 = 40%
```

**Conclusion :** 40% de tous les utilisateurs ont regardé les deux films.

---

### 2.4 Différence entre Confidence et Support

| Métrique | Formule | Question | Interprétation |
|----------|---------|----------|----------------|
| **Confidence** | \|𝒰ᵢ ∩ 𝒰ⱼ\| / \|𝒰ᵢ\| | "Si i, alors j ?" | **Fiabilité** de la règle |
| **Support** | \|𝒰ᵢ ∩ 𝒰ⱼ\| / \|𝒰\| | "Combien font i ET j ?" | **Fréquence** du pattern |

**Exemple comparatif :**

```
Règle A : Film_obscure → Film_culte
- Support = 0.01 (1% des users)
- Confidence = 0.95 (95% de ceux qui ont vu film_obscure)

Règle B : Blockbuster1 → Blockbuster2
- Support = 0.40 (40% des users)
- Confidence = 0.60 (60% de ceux qui ont vu blockbuster1)
```

**Trade-off :**
- Règle A : **Forte confiance** mais **peu fréquente** (niche)
- Règle B : **Fréquente** mais confiance modérée

### 2.5 Utilisation des Association Rules

#### Algorithme de Recommandation

**Input :** Utilisateur u a regardé item i

**Processus :**
1. Trouver toutes règles de forme : **i → j**
2. Trier règles par **Confidence** (descendant)
3. Filtrer règles avec **Support** minimum (ex: > 5%)
4. Recommander Top-N items j

**Exemple :**

```
User nouveau regarde : Barbie 🎬

Règles trouvées :
┌──────────────────┬────────────┬─────────┐
│ Règle            │ Confidence │ Support │
├──────────────────┼────────────┼─────────┤
│ Barbie → Wonka   │    1.0     │  0.20   │
│ Barbie → Film4   │    1.0     │  0.20   │
│ Barbie → Anatomy │    0.5     │  0.20   │
│ Barbie → Marvels │    0.5     │  0.20   │
│ Barbie → Migr.   │    0.5     │  0.20   │
└──────────────────┴────────────┴─────────┘

Recommandations Top-3 :
1. Wonka (conf: 100%)
2. Film4 (conf: 100%)
3. Anatomy (conf: 50%)
```

### 2.6 Avantages et Limitations

**✅ Avantages :**
- **Simple et interprétable** : "Ceux qui ont aimé X ont aussi aimé Y"
- **Pas de cold-start utilisateur** : Fonctionne dès première interaction
- **Rapide** : Pré-calcul des règles offline
- **Explainable** : Facile à justifier auprès utilisateur
- **Scalable** : Matrices sparses, algorithmes efficaces (Apriori, FP-Growth)

**❌ Limitations :**
- **Non-personnalisé** : Ne prend pas en compte profil utilisateur complet
- **Popularity bias** : Items populaires dominent
- **Cold-start items** : Nouveaux items pas dans règles
- **Pas de diversité** : Tend à recommander items similaires
- **Statique** : Règles doivent être recalculées périodiquement

---

### 2.7 Variantes et Extensions

#### 2.7.1 Règles séquentielles

Au lieu de co-occurrence, considérer l'**ordre temporel** :

```
Si user regarde A, puis B → recommander C
```

**Exemple :**
```
Marvel Phase 1 → Phase 2 → Phase 3
```

#### 2.7.2 Multi-item rules

Règles avec plusieurs antécédents :

```
{Barbie, Wonka} → Migration
"Si user aime Barbie ET Wonka, recommander Migration"
```

#### 2.7.3 Contextual rules

Intégrer contexte :

```
{Film_romantique, Weekend, Couple} → Film_romantique_2
```

## 3. 🚀 Vers les Recommandations Personnalisées {#towards-personalized}

### 3.1 Limitations des Approches Non-Personnalisées

Bien que simples et efficaces, les recommandations non-personnalisées ont des limites :

1. **Manque de pertinence individuelle**
   - Ignore préférences spécifiques
   - Recommandations génériques

2. **Pas d'adaptation**
   - Ne s'améliore pas avec données utilisateur
   - Même liste pour tous

3. **Popularité écrasante**
   - Items de niche ignorés
   - Long tail non exploité

4. **Pas de serendipity**
   - Prévisible
   - Pas de découvertes surprenantes

---

### 3.2 Approches de Recommandations Personnalisées

Pour dépasser ces limitations, plusieurs approches existent :

#### 3.2.1 Collaborative Filtering (Filtrage Collaboratif)

**Principe :**
> "Les utilisateurs similaires aiment des items similaires"

**Types :**
- **User-User CF** : Trouver utilisateurs similaires
- **Item-Item CF** : Trouver items similaires
- **Matrix Factorization** : Décomposition matricielle (SVD, ALS)

**Exemple :**
```
User A et User B aiment {Film1, Film2, Film3}
User A a aussi aimé Film4
→ Recommander Film4 à User B
```

**Avantages :**
- Personnalisation forte
- Découverte d'items non évidents
- Pas besoin de métadonnées items

**Inconvénients :**
- Cold-start (users et items)
- Sparsité des données
- Scalabilité

---

#### 3.2.2 Content-Based Filtering (Filtrage basé sur le Contenu)

**Principe :**
> "Recommander items similaires à ceux que l'utilisateur a aimés"

**Processus :**
1. Extraire features des items (genres, acteurs, etc.)
2. Créer profil utilisateur basé sur items aimés
3. Recommander items similaires au profil

**Exemple :**
```
User aime : {SciFi, Harrison Ford, Space}
→ Recommander : Blade Runner, Star Wars, Interstellar
```

**Avantages :**
- Pas de cold-start items (si métadonnées disponibles)
- Explainability
- Indépendant d'autres utilisateurs

**Inconvénients :**
- Overspecialization (filter bubble)
- Nécessite métadonnées de qualité
- Pas de serendipity

---

#### 3.2.3 Hybrid Approaches (Approches Hybrides)

**Principe :**
> Combiner **plusieurs méthodes** pour tirer parti de leurs forces respectives.

**Types de combinaisons :**

1. **Weighted Hybrid**
   ```
   Score = α × CF_score + β × CBF_score
   ```

2. **Switching Hybrid**
   - Utiliser CF si assez de données
   - Sinon utiliser CBF

3. **Cascade Hybrid**
   - Filtrer avec une méthode
   - Affiner avec une autre

4. **Feature Combination**
   - Combiner features de CF et CBF dans un modèle ML

**Avantages :**
- Meilleure robustesse
- Atténue faiblesses individuelles
- Performance généralement supérieure

---

#### 3.2.4 Context-Aware Approaches (Approches Contextuelles)

**Principe :**
> Intégrer le **contexte** dans les recommandations (temps, lieu, device, compagnie, etc.)

**Dimensions contextuelles :**
- **Temporel** : Heure, jour, saison
- **Spatial** : Localisation géographique
- **Social** : Seul ou en groupe
- **Device** : Mobile, desktop, TV
- **Météo** : Pluie, soleil

**Exemple :**
```
User + Film romantique + Vendredi soir + En couple
→ Recommander : Film romantique populaire

User + Documentaire + Lundi matin + Seul + Trajet
→ Recommander : Documentaire court (podcast)
```

**Techniques :**
- **Pre-filtering** : Filtrer items selon contexte
- **Post-filtering** : Ajuster recommandations selon contexte
- **Contextual modeling** : Intégrer contexte dans modèle
  - Tensor Factorization
  - Factorization Machines

**Avantages :**
- Pertinence situationnelle
- Adaptation dynamique
- Meilleure satisfaction utilisateur

---

### 3.3 Évolution Progressive

```
┌─────────────────────────────────────────────────────────┐
│  Non-Personnalisé → Semi-Personnalisé → Personnalisé    │
└─────────────────────────────────────────────────────────┘

1. Popularity           : Tout le monde voit pareil
2. Association Rules    : Basé sur item consulté
3. Demographics         : Segmentation par profil
4. Collaborative Filter : Basé sur utilisateurs similaires
5. Hybrid + Context     : Personnalisation complète
```

**Stratégie recommandée :**

```
Nouveau système :
├─ Étape 1 : Popularity + Association Rules (baseline)
├─ Étape 2 : Ajouter Collaborative Filtering
├─ Étape 3 : Intégrer Content-Based
├─ Étape 4 : Hybridation
└─ Étape 5 : Context-aware + Deep Learning
```

## 4. 📊 Résumé et Comparaison

### 4.1 Tableau Comparatif

| Critère | Non-Personnalisé | Personnalisé |
|---------|-----------------|--------------|
| **Données utilisateur** | Non nécessaires | Essentielles |
| **Cold-start** | ✅ Aucun problème | ❌ Problématique |
| **Pertinence** | ⭐⭐ Générique | ⭐⭐⭐⭐⭐ Adaptée |
| **Complexité** | ⭐ Simple | ⭐⭐⭐⭐ Complexe |
| **Scalabilité** | ✅ Excellente | ⚠️ Challenges |
| **Diversité** | ❌ Faible | ✅ Possible |
| **Explainability** | ✅ Facile | ⚠️ Variable |
| **Cas d'usage** | Homepage, Nouveaux users | Users établis |

---

### 4.2 Quand Utiliser Quoi ?

**Non-Personnalisé (Association Rules, Popularity) :**
- ✅ Nouveaux utilisateurs (cold-start)
- ✅ Homepage pour visiteurs anonymes
- ✅ Baseline pour comparaison
- ✅ Fallback quand personnalisation échoue
- ✅ Quick wins / Prototypage rapide

**Personnalisé (CF, CBF, Hybrid) :**
- ✅ Utilisateurs avec historique
- ✅ Maximiser engagement et satisfaction
- ✅ Découverte personnalisée
- ✅ Fidélisation utilisateurs
- ✅ Systèmes matures en production

**Recommandation pragmatique :**
> Commencer avec **Non-Personnalisé** (simple, robuste), puis progressivement ajouter **Personnalisation** à mesure que données et ressources augmentent.

---

## Conclusion

Les **recommandations non-personnalisées**, notamment via **Association Rules**, constituent :

✅ Un **excellent point de départ** pour tout système de recommandation  
✅ Une **solution efficace** pour cold-start et nouveaux utilisateurs  
✅ Un **baseline solide** pour évaluer approches plus sophistiquées  
✅ Un **composant utile** même dans systèmes personnalisés (fallback)  

Cependant, pour maximiser pertinence et engagement, la progression vers **recommandations personnalisées** (CF, CBF, Hybrid, Context-aware) est essentielle.

> "Start simple, scale smart" - La clé est de trouver le bon équilibre entre simplicité et personnalisation selon les besoins et ressources disponibles.
