# Filtrage Collaboratif - Guide Complet

## 1. Introduction au Feedback Implicite

Le **feedback implicite** représente les interactions des utilisateurs qui ne sont pas des évaluations explicites (notes, likes). Par exemple : vues, clics, achats, temps passé sur un contenu.

### Caractéristiques du feedback implicite
- **Positif uniquement** : on observe ce que l'utilisateur a consulté/acheté, mais pas ce qu'il n'aime pas
- **Ambiguïté** : une interaction ne signifie pas toujours un intérêt réel
- **Abondance** : beaucoup plus de données disponibles que le feedback explicite

---

## 2. Approches pour Augmenter les Datasets Implicites

### 2.1 All Missing As Negative (AMAN)
**Principe** : Convertir le feedback implicite en ratings binaires
- Interactions observées → valeur **1** dans la matrice
- Interactions non observées → valeur **0**

**Problème** : 
- Le modèle devient fortement biaisé vers le feedback négatif
- Tendance à toujours prédire 0
- Résultats médiocres en pratique

### 2.2 All Missing As Unknown (AMAU)
**Principe** : Ignorer complètement les interactions non observées
- Ne considérer que les interactions positives
- Traiter les cases vides comme inconnues

**Problème** :
- Biais fort vers le feedback positif
- Mène à une solution triviale (tout est recommandé)
- Pas de discrimination entre items

### 2.3 Solution Intermédiaire (In-between)
**Principe** : Discriminer les items négatifs des non observés

**Deux approches** :
1. **Échantillonnage aléatoire** : sélectionner aléatoirement des items négatifs
2. **Techniques de pondération** : assigner des poids différents selon la confiance

---

## 3. One-Class Collaborative Filtering

### Concept
Approche spécifique pour traiter le feedback positif uniquement en :
- Transformant l'ensemble d'observations implicites par l'ajout de feedback négatif artificiel
- Adaptant la fonction objectif pour gérer cette asymétrie

---

## 4. Weighted Regularized Matrix Factorization (WRMF)

### Principe de base
Utiliser des **poids** pour indiquer le niveau de confiance dans chaque observation.

### Interprétation des poids
- **Si l'utilisateur u a interagi avec l'item i** → haute confiance que u aime i
- **Sinon** → on fait des hypothèses avec différents niveaux de confiance

### Fonction objectif

```
ℒ(P, Q) = Σ c_ui(r_ui - p_u q_i^T)² + λΩ(P) + λΩ(Q)
        (u,i)∈D
```

Où :
- **r_ui** : rating observé (1 si interaction, 0 sinon)
- **c_ui** : poids de confiance pour l'observation (u,i)
- **p_u** : vecteur latent de l'utilisateur u
- **q_i** : vecteur latent de l'item i
- **λ** : coefficient de régularisation
- **Ω(P), Ω(Q)** : termes de régularisation

### Définition de c_ui
Deux approches possibles :
1. **Valeurs constantes** pour observations positives vs négatives
2. **Paramètres additionnels** appris pendant l'entraînement

### Optimisation
- **ALS (Alternating Least Squares)** est utilisé quand c_ui est constant pour les items non observés
- Permet une optimisation efficace en alternant entre la mise à jour de P et Q

## 5. Bayesian Personalized Ranking (BPR)

### Philosophie
Plutôt que de prédire des ratings absolus, **BPR se concentre sur l'ordre de préférence** entre items.

### Construction des données d'entraînement

À partir des interactions observées, on crée des **préférences par paires** :

```
D_bpr = {(u, i, j) | i ∈ I_u ∧ j ∈ I \ I_u}
```

Où :
- **u** : utilisateur
- **i** : item avec lequel u a interagi (préféré)
- **j** : item avec lequel u n'a PAS interagi (moins préféré)
- **I_u** : ensemble des items consommés par u
- **I** : ensemble de tous les items

### Interprétation visuelle
Le tableau montre la transformation :
- **1** (interactions observées) → **B** dans la colonne de l'item i
- **cases grises** (non observées) → items j à comparer
- On génère des triplets (u, i, j) indiquant que u préfère i à j

### Fonction objectif

L'objectif est de maximiser :

```
p(Θ | >_u) ∝ p(>_u | Θ) p(Θ)
```

Avec :
- **p(i >_u j | Θ)** = σ(r̂_uij(Θ)) : probabilité que u préfère i à j
- **r̂_uij** = r̂_ui - r̂_uj : différence entre les scores prédits

### Critère BPR-OPT

```
BPR-OPT := ln p(Θ | >_u)
         = ln p(>_u | Θ) p(Θ)
         = Σ ln σ(r̂_uij) - λ_Θ ||Θ||²
         (u,i,j)∈D_bpr
```

### Optimisation
- **SGD (Stochastic Gradient Descent)** : mise à jour itérative des paramètres
- **Échantillonnage uniforme** des triplets depuis D_bpr
- Les triplets sont échantillonnés à chaque itération

### Avantages de BPR
- Directement aligné avec l'objectif de ranking
- Gère naturellement le feedback implicite positif
- Performance empirique souvent supérieure à WRMF

## 6. Récapitulatif des Approches de Filtrage Collaboratif

### Approches basées sur la mémoire (Memory-based)
- **User-based neighborhood** : trouver des utilisateurs similaires
- **Item-based neighborhood** : trouver des items similaires
- **Mesures de similarité** : cosinus, corrélation de Pearson, etc.

### Approches basées sur des modèles (Model-based)
- **Matrix Factorization** : décomposition de la matrice user-item
- **SVD** : Singular Value Decomposition
- **Minimisation de l'erreur quadratique** : optimisation classique
- **Apprentissage des paramètres** : SGD, ALS
- **Gestion du feedback implicite** : **WRMF**, **BPR**

---

## 7. Comparaison WRMF vs BPR

| Aspect | WRMF | BPR |
|--------|------|-----|
| **Type de fonction** | Point-wise (prédit chaque rating) | Pair-wise (prédit l'ordre relatif) |
| **Objectif** | Minimiser l'erreur de prédiction | Maximiser la probabilité de l'ordre correct |
| **Optimisation** | ALS | SGD |
| **Pondération** | Explicite via c_ui | Implicite via échantillonnage |
| **Flexibilité** | Peut ajuster les poids de confiance | Focus naturel sur le ranking |

---

## 8. Concepts Clés à Retenir

1. **Feedback implicite positif uniquement** : nécessite des techniques spécifiques
2. **WRMF** : introduit des poids de confiance dans la factorisation matricielle
3. **BPR** : transforme le problème en apprentissage de préférences par paires
4. **ALS vs SGD** : deux méthodes d'optimisation avec des trade-offs différents
5. **Ranking vs Rating** : BPR optimise directement pour le ranking, plus pertinent pour les recommandations
